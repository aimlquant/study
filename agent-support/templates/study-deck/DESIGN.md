# study-deck-v1 공용 덱 디자인 규칙

이 템플릿은 발표자의 자체 출판 템플릿 `ai-odyssey-publisher`의 정보 위계와 발표 UX를 AIML Quant에 맞게 옮긴 1280×720 HTML 덱이다. 발표 형식의 정본은 아래 공용 파일이며, 특정 회차 완성본을 복사하거나 별도로 찾아볼 필요가 없다.

- 기본 HTML: `agent-support/templates/study-deck/index.html`
- 공용 스타일·동작: 같은 디렉터리의 `assets/deck.css`, `assets/deck.js`, `assets/deck-lightbox.js`, `assets/katex/`
- 공통 설계 청사진: `agent-support/templates/STUDY_SESSION_BLUEPRINT.md`

한 회차의 기본 산출물은 상세 리포트와 발표자료의 쌍이다. 원자료에서 리포트를 먼저 완성·검증하고 덱의 내용은 그 리포트에서 파생한다. 공용 템플릿은 외형과 레이아웃의 기준이고, 리포트는 내용·용어·근거의 기준이다.

## 기본 화면 구조

표지는 `.slide--cover`의 브랜드, 제목·부제, 발표자·범위·발표일을 사용한다. 표지 외에는 도입·절 첫 설명·본문·확인 질문·마무리를 모두 `.slide.slide--teaching`으로 작성하고 다음 직접 자식 순서를 유지한다.

```text
header.slide-header     AIML Quant 브랜드 + section-tag의 챕터 또는 원본 좌표
h1                      원본 절의 정확한 제목 또는 후속 설명의 결론형 제목
p.lead                  질문·배경·비교 조건
div.slide-body          행 설명·카드·그림·수식·코드·표
p.takeaway              본문에서 이어지는 결론 또는 해석 조건
footer.slide-footer     정확한 report.html#id 링크 + 현재 번호 / 전체 장수
```

`takeaway`와 `footer`는 `.slide-body` 바깥에 둔다. 모든 본문 footer에는 `.report-ref`, `[data-slide-number]`, `[data-slide-total]`을 남긴다. 제목·lead·takeaway에서 같은 결론을 반복하지 않는다. 글이 길면 설명을 연속 화면으로 나누며, 공간을 확보하려고 헤더·절 표시·푸터를 제거하거나 글자를 줄이지 않는다.

공용 CSS의 `.slide--teaching`은 여백 26px 52px 22px, 제목 35px, lead 20px, 본문 행 설명 22px, 표 21px를 기본으로 한다. 우측 상단 설정, 좌측 상단 목차, 하단 이동 버튼·진행률, 키보드·해시 이동과 이미지 확대도 템플릿 그대로 유지한다. 실제 내용의 길이와 그림 비율은 최종 크기 렌더로 확인한다.

## 복제할 레이아웃

기본 HTML에는 완전한 section 예시가 있다. 아래 ID의 section 전체를 복제한 뒤 고유 `id`와 `aria-label`, 내용, 원본 좌표, 리포트 참조·링크를 바꾼다. 이 목록은 발표의 고정 목차나 장수 제한이 아니다.

| 예시 ID | 용도와 본문 컴포넌트 |
|---|---|
| `slide-cover` | 표지와 회차 메타데이터 |
| `slide-opening` | 핵심 질문 세 개, `.teaching-columns` |
| `slide-roadmap` | 절 순서의 학습 흐름, `.teaching-rows` |
| `slide-section` | 장·주요 절 구분, 중앙에 번호와 정확한 원본 제목을 함께 배치 |
| `slide-definition` | 절 첫 설명, 정의·원리·조건 |
| `slide-example` | 입력·결과 또는 두 관점, 두 열 `.teaching-columns` |
| `slide-figure` | 왼쪽 그림과 오른쪽 읽는 법·관찰·해석 경계, `.teaching-visual` |
| `slide-wide-figure` | 전체 폭 그림과 하단 해설, `.teaching-wide-visual` |
| `slide-formula` | `.formula-main`의 KaTeX 수식과 기호·계산 설명 |
| `slide-code` | 언어를 표시한 코드와 입력·계산 설명 |
| `slide-result` | 실제 출력과 해석, `.teaching-table` |
| `slide-comparison` | 같은 필드의 비교표, `.teaching-table` |
| `slide-checkpoint` | 본문 근거로 답하는 확인 질문 |
| `slide-closing` | 같은 본문 형식의 정리·질의응답과 자료 링크 |

두 그림 예시는 같은 자산을 좌우형·전체 폭형으로 보여 주는 대안이다. 실제 덱에는 읽기 좋은 쪽을 선택하고, 같은 그림을 예시 수에 맞춰 중복 배치하지 않는다. 장·주요 절 전환에는 `slide-section` 구분 장을 두고 이어지는 `slide-definition`에서 설명한다. 번호는 제목 바로 위에 작게 두고, 정확한 번역 제목을 중앙의 주 요소로 쓴다. 상단 제목과 본문 숫자를 멀리 떨어뜨리지 않는다. 가장 긴 제목도 글자를 줄이지 않고 자연스럽게 줄바꿈한다. 구분 장 자체는 설명 커버리지로 세지 않는다.

50분 발표와 10분 질의응답을 기준으로 설명 단위를 먼저 설계하고 실제 설명 시간을 배정한다. 원본 장·절 순서와 질문을 보존하며, 필요한 레이아웃만 선택·복제·제거한다. 템플릿의 대괄호 문구, 예시 절 번호·수식·코드는 발행 전에 실제 리포트 내용으로 모두 교체한다.

## 핵심 원칙

- 배경은 따뜻한 회백색, 액센트는 진청 한 색을 기본으로 사용한다.
- 한 슬라이드에는 하나의 메시지만 두고 제목, 한 줄 설명, 본문, takeaway 순서로 읽히게 한다.
- 한 슬라이드에는 의미 있는 그림 하나만 두는 것을 기본으로 한다. 서로 다른 그림의 동시 비교가 학습 과제이고 두 그림이 최종 크기에서 모두 읽힐 때만 한 장에 함께 둔다.
- 제목은 사실 이름보다 결론형 문장으로 쓴다. `기술 A의 특징`보다 `기술 A는 검증 비용을 줄인다`가 낫다.
- 단, 원본 절 구분 슬라이드와 각 소절의 첫 슬라이드는 해설판의 정확한 번역 제목을 주 제목으로 사용한다. 같은 소절의 후속 슬라이드에서 결론형 제목을 사용한다.
- 결론형 제목 가까이에 `교재 §3.2.2`, `Listing 3.7–3.8`처럼 간결한 원본 학습 좌표를 표시한다. 원본 그림 좌표는 추적 메타데이터와 근접 출처에 보존하되 발표자료 자체의 그림 번호로 사용하지 않는다.
- 기본 글자 크기를 줄여 내용을 밀어 넣지 않는다. 내용이 넘치면 슬라이드를 나눈다.
- 같은 의미 층위의 카드는 `.teaching-columns`의 공통 열 너비·상하선을 맞춘다. 좁은 열에 설명이 몰리면 행 설명이나 다음 화면으로 나누며 카드마다 글자 크기를 바꾸지 않는다.
- 표지, 행 설명, 카드, 좌우형·전체 폭형 그림, 수식, 코드, 표와 정리 예시를 내용에 맞게 선택한다.
- 외부 폰트, CDN, 프레임워크 없이 발표 폴더만으로 동작해야 한다.
- 템플릿 CSS와 JavaScript는 발표 폴더에 복사한다. 과거 발표에 일괄 덮어쓰지 않는다.

## 공용 컴포넌트와 호환성

새 덱의 기본값은 위 `slide--teaching` 예시와 공용 CSS다. `.teaching-columns`, `.teaching-rows`, `.teaching-table`, `.teaching-visual`, `.teaching-wide-visual`, `.formula-main`을 내용에 맞춰 사용한다. `.deck-report-figure`는 캡션 띠 없는 그림을, `.report-ref`는 같은 슬라이드의 `data-report-refs`에 포함된 정확한 리포트 anchor를 연결한다.

CSS에는 기존 덱의 `.slide--section`, `.slide--closing`, `.panel`, `.card-grid`, `.compare-table`, `.slide--visual` 등도 남아 있다. 이들은 기존 자료의 호환성을 위한 선택지이며, 새 덱의 기본 외형은 `index.html`의 예시를 따른다. 회차별 CSS·JS는 생성 당시 스냅샷으로 보존하고 기존 발표에 공용 파일을 일괄 덮어쓰지 않는다.

## 리포트·슬라이드·목차 연결

- 리포트 게이트를 통과하기 전에는 생성된 구조 청사진을 회차별 슬라이드 본문으로 채우지 않는다.
- 리포트의 각 핵심 절을 질문·정의·원리·근거·조건을 설명하는 연속 화면에 대응시킨다. 절당 장수를 미리 고정하지 않는다. 제목만 있는 구분 장과 refs 표지만으로 설명 커버리지를 채우지 않는다.
- 리포트 표·도형이 발표 화면에서 읽히면 같은 `src`의 SVG·이미지를 직접 재사용한다. 복잡한 표·도형은 의미·번호·관계를 유지하며 발표에서 읽을 부분을 CSS/SVG로 재배치하고 정확한 리포트 그림 anchor를 표시한다.
- 슬라이드의 `aria-label`은 화면 제목보다 짧고 구체적인 목차 항목이다. `deck.js`가 이 값을 사용해 목차를 자동 생성한다.
- 절 첫 설명 화면은 정확한 원본 제목을 보여 주고, `aria-label`은 해당 절의 구체적인 주제로 쓴다.
- 리포트와 슬라이드는 같은 용어·논리 순서를 쓰되 문장 밀도는 각 문서의 용도에 맞춘다. 리포트의 그림·표와 덱의 실제 데이터 표는 각 문서의 읽기 순서대로 번호를 붙이고, 덱의 그림 아래 캡션 줄은 생략한다.
- 덱 `<main>`에는 `data-report-source="report.html"`, 모든 `.slide`에는 근거가 된 리포트 ID를 `data-report-refs`로 둔다.
- 원본 본문 절은 `data-source-refs="section:3.1 section:3.1.1"`처럼 기록하고 같은 좌표를 화면에도 표시한다. 그림·표·Listing·Example을 직접 설명하는 슬라이드는 해당 종류의 좌표도 기록한다.
- 원본 그림의 의미는 슬라이드 제목·본문·alt에 보존한다. 그림 바로 아래 `그림 N | 제목` 형태의 한 줄 표·띠·figcaption을 추가하지 않는다. 그림을 읽는 데 필요한 단위·조건·출처가 캡션에만 있었다면 가까운 본문·링크에 남긴다. 실제 데이터 표와 상세 리포트의 캡션은 유지한다.
- 원본 section마다 정확히 한 슬라이드에 `data-source-title="section:3.1.1"`를 둔다. 그 슬라이드는 같은 section 토큰을 `data-source-refs`에도 포함하고 정확한 번역 제목을 화면에 보여 준다. 그룹 divider의 선행 참조는 제목 책임을 대신하지 않는다.
- 리포트의 모든 `.report-section`과 `data-deck-use="required"` 그림을 적어도 한 번 참조한다. Report 링크는 가능하면 정확한 `report.html#<id>`로 연결한다.

## 편집 규칙

1. 기본 HTML의 안내 문장을 교재 근거와 발표자의 해설로 모두 교체한다.
2. 각 `<section class="slide">`에 내용을 설명하는 고유한 `aria-label`을 둔다.
3. 각 슬라이드의 주장·표·도형이 나온 리포트 절·표·그림 ID를 `data-report-refs`에 기록한다.
4. 이미지에는 구체적인 `alt`를 적고 회차 `assets/` 아래에 저장한다.
5. 인용, 데이터와 외부 이미지는 해당 슬라이드의 `.source-note`에 근접 출처를 표시한다.
6. 표는 반복되는 필드를 비교할 때만 사용하고, 본문 글자 크기를 줄여 표를 욱여넣지 않는다.
7. 기본 제공 키보드 이동, 자동 목차, 진행률, 우측 상단 설정 패널, 테마, 전체화면 코드를 제거하지 않는다.
8. 표지 외 모든 화면의 `.slide-header`·`.section-tag`·`.slide-footer`와 footer 안의 리포트 anchor·현재/전체 번호를 유지한다. 설정 패널의 `Index / Slides / Report` 링크와 마무리 슬라이드의 보고서·회차 목록 링크를 유지한다.
9. 기본 HTML의 프롬프트·안내 문장, 제작 파이프라인, 슬라이드 수와 본편/부록 운영 방식, 검토 과정 표현을 공개 산출물에 남기지 않는다. 표지·개요·목차·takeaway는 제작 규약 준수가 아니라 실제 주제의 질문·설계 계약·근거·한계를 말해야 한다.
10. 블록 코드에는 `<pre data-code-language="Cypher">` 또는 직계 `<code class="language-cypher">`처럼 실제 언어를 지정한다. 공용 CSS가 언어 라벨과 코드 창 헤더를 표시하므로 일반 패널처럼 보이는 무표식 코드 블록을 남기지 않는다.
11. 낯선 용어는 처음 등장할 때 한 문장으로 정의한다. 그림에는 읽는 순서, 실제로 관찰할 관계·결과, 해석 경계를 설명하는 본문을 둔다. 같은 화면 또는 명시적으로 연결한 연속 화면에서 이 역할을 수행하며 제목·출처만 있는 캡션으로 대신하지 않는다. 넘치면 설명을 삭제하거나 글자를 줄이지 말고 화면을 나눈다.
12. 둘 이상의 `figure:` 좌표를 한 슬라이드에서 설명하는 실제 동시 비교는 `data-figure-comparison="intentional"`을 두고, 두 그림이 최종 프로젝터 크기에서 모두 읽힐 때만 허용한다.
13. `.code-layout`의 좁은 우측 열에는 단일 `.panel`만 둔다. `.kpi-grid`·`.decision-grid`처럼 전체 폭을 전제로 한 다열 컴포넌트를 그 안에 중첩하면 각 셀이 지나치게 좁아져 한글이 어절 중간에서 깨진다. 래퍼만 없애 세로로 쌓으면 가로 문제가 stage 세로 넘침으로 바뀌므로, 다열 비교가 꼭 필요하면 전체 폭 레이아웃이나 별도 슬라이드로 나눈다.
14. 낯선 알고리즘은 질문·입출력 도해·작동 원리·최소 코드·기록된 실행 결과·해석과 실패 경계 순으로 설명한다. 코드가 있는 실험은 가능한 경우 다음 슬라이드나 같은 화면의 읽을 수 있는 차트·표와 연결하고, 노트북에 없는 결과를 꾸며 내지 않는다.
15. 수식은 계산 대상과 기호를 가까운 본문에서 풀어 쓰고, 약어·단위는 첫 등장에 원어와 실제 크기까지 설명한다. 정확도와 수익률, 비용 차감 전후 지표를 같은 성과처럼 표현하지 않는다.
16. Python 적응 자료에서는 Python API와 실행 의미를 직접 설명한다. 원본 언어의 매개변수명, 이식 과정, `AIML Quant 재현 코드다` 같은 제작 메모를 코드 캡션으로 남기지 않는다.
17. 그림의 정체성과 읽는 법은 제목·본문에서 제공하고, alt와 figure의 `data-deck-figure-title`은 접근성·확대 보기의 식별 정보로 둔다. 긴 해석은 본문이나 다음 슬라이드로 옮기고, 개념 모식도와 실제 측정 결과를 같은 종류의 증거처럼 보이게 하지 않는다.

## 품질 기준

- 1280×720과 1366×768에서 제목·본문·footer가 겹치거나 잘리지 않는다.
- 프로젝터 화면에서 본문·표·근접 출처가 육안으로 읽혀야 한다. 작은 `source-note`를 면죄부로 삼아 핵심 조건·수치·경계를 축소하지 않는다.
- 390px 모바일에서 덱이 화면 안에 축소되고 버튼과 목차를 사용할 수 있다.
- 키보드 ←/→, Home/End, 목차 이동, 테마, 전체화면, 해시 URL이 동작한다.
- 모든 본문 그림은 클릭과 Enter/Space로 확대 뷰어를 열고, 휠·버튼 확대, 드래그 이동, Esc 닫기와 원래 그림으로의 포커스 복귀가 동작한다.
- 모든 블록 코드에 언어 라벨과 코드 창 헤더가 보인다.
- 우측 상단 설정 아이콘이 리포트와 같은 위치·형태로 보이고 `Index / Slides / Report` 링크가 모두 동작한다.
- 표지 외 모든 화면에 공통 헤더·절 표시·푸터·리포트 anchor·현재/전체 번호가 있다. 원본 절 첫 화면은 정확한 번역 제목을, 후속 화면은 결론형 제목을 쓰고 takeaway와 필요한 근접 출처를 갖춘다.
- 리포트의 그림·표와 덱의 데이터 표 번호가 각각 연속된다. 덱의 그림 아래 캡션 줄은 생략하며, 명시적으로 번호를 요청받은 경우에만 현재 보이는 그림 순서로 번호를 붙인다.
- 본문·표·캡션의 기본 글자가 프로젝터 크기에서 읽히며, 전체화면 확대가 기본 가독성을 대신하지 않는다.
- 발표자 설명을 듣지 않고 화면을 순서대로 읽어도 질문·중간 원리·근거·조건의 연결을 따라갈 수 있다. 발표자 노트는 추가 설명이며 화면의 의미 누락을 대신하지 않는다.
- 그림의 해석이 실제 축·노드·화살표와 대응하며, 제목과 출처만으로 끝나지 않는다.
- 실험은 입력·시간 조건 → 계산 → 실제 결과 → 해석·한계가 연속 화면에서 이어진다. 리포트에 결과가 없는 경우 실행 상태와 생략 이유를 기록한다.
- 낯선 수식의 모든 기호와 지표의 단위·계산 대상이 가까운 화면에서 설명된다. 도입·요약·질문은 해당 장의 실제 논증에서 나온다.
- 모든 `data-report-refs`가 실제 리포트 ID이고, 모든 본문 절과 필수 그림이 발표자료에서 빠짐없이 다뤄진다.
- 인쇄/PDF에서 한 슬라이드가 한 페이지로 출력되고 제어 버튼은 숨겨진다.

새 교재 덱의 설명 대응·해시·노트북 이월 기록은 제작 절차 §9의 `report-teaching-v1` 계약을 따른다. main에 `data-caption-scope="deck" data-figure-captions="none"`을 둔다. 실제 표의 자체 캡션은 `data-deck-caption="table"`로 덱 순서대로 번호를 붙인다. 명시적으로 번호 있는 그림 캡션을 요청받은 경우에만 생략 정책을 제거하고 `data-deck-caption="figure"`를 사용한다. 리포트 번호를 적은 링크는 리포트 대상 번호를 유지한다.

공용 템플릿을 수정한 뒤에는 `new-presentation.py --site <임시 디렉터리>`로 리포트와 덱을 함께 생성해 검사한다. 생성기가 두 템플릿의 자산을 합치므로 템플릿 폴더를 직접 연 화면만으로 판단하지 않는다. `test_presentation_template.py`는 생성된 각 본문 화면의 공통 구조·리포트 연결·로컬 자산을 검사한다. 구조 검사 통과 뒤 모든 예시를 실제 데스크톱과 모바일 크기로 렌더해 확인한다.
