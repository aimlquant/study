# 공용 덱 템플릿 형식 정비

## 확인한 문제와 변경

공용 덱 HTML의 본문 예시에 헤더·절 표시·푸터·리포트 anchor·슬라이드 번호가 없어, 같은 생성기를 사용해도 공통 발표 형식이 보존되지 않았다. 제작 지침은 공용 템플릿과 별도의 과거 회차를 기준으로 안내하고 있었다.

`agent-support/templates/study-deck/index.html`을 표지 포함 13개의 완전한 section 예시로 정비했다. 표지 외 12개 화면은 `header → h1 → lead → slide-body → takeaway → footer`를 사용하며, footer에 실제 리포트 anchor와 현재/전체 번호를 둔다. 예시는 행 설명, 두 열·세 열 카드, 그림과 옆 해설, 전체 폭 그림, 수식, 코드, 출력표, 비교표, 확인 질문, 정리를 제공한다. 예시 개수는 실제 발표의 장수나 목차를 고정하지 않는다.

템플릿의 리포트 참조는 함께 생성되는 리포트의 실제 ID에 맞췄다. 두 그림 화면은 같은 자산의 배치 대안이며, 실제 덱에 중복 배치할 의무가 없음을 명시했다. 기존 공용 CSS·JS의 발표 스타일을 사용하고, 기존 회차 산출물은 변경하지 않았다.

공용 덱 DESIGN, 회차 청사진, 제작 절차, study-presentation 스킬이 공용 HTML·CSS·JS를 형식의 정본으로 안내하도록 맞췄다. 리포트 DESIGN의 과거 회차 참조도 공용 리포트 템플릿으로 바꿨다. 회차 완성본 URL을 새 기준으로 추가하지 않았다.

## 재발 방지와 검증

`test_presentation_template.py`에 실제 paired 생성 결과의 DOM 관계를 확인하는 검사를 추가했다. 모든 본문 화면의 직접 자식 순서, 헤더·절 표시, 푸터 안의 리포트 링크와 현재/전체 번호, 고유 슬라이드 ID, 리포트 참조의 실재, 재사용 그림과 로컬 자산을 검사한다. 원본 줄 수나 고정 슬라이드 수를 합격 기준으로 사용하지 않는다.

- 현재 템플릿 검사 8개 통과.
- 수정 전 템플릿을 별도 임시 디렉터리에 넣으면 새 회귀 검사에서 7개 검사 실패를 확인했다. 이는 과거 누락이 다시 생겼을 때 잡히는지 확인한 의도된 실패다.
- 교재 저장소를 `materials`로 연결한 전체 테스트: 285개 실행, 280개 통과, 선택 의존성(httpx·neo4j·openai)이 없는 5개 건너뜀.
- 사이트 build와 build --check 통과. `validate-site.py --site html --check-materials`도 100개 HTML에서 통과했다. 기존 외부 iframe 등 경고 22개가 있으며 공개 산출물 변경은 없다.
- 스킬 quick_validate 통과. 스킬 description과 외부 작업 권한은 변경하지 않았다.

## 렌더 확인 기록

`new-presentation.py --site <임시 디렉터리>`로 실제 생성한 리포트·덱과 병합된 자산을 검증했다. 캡처는 owner-installed safe-browser-shot만 사용했다.

1366×768 및 1600×900에서 13개 예시를 각각 원본 크기로 열어 헤더·본문·카드·그림·수식·코드·표·푸터를 확인했다. 모바일 초기 캡처에서는 QA 전용 CSS가 이동 버튼 폭을 136px로 가정해 오른쪽 끝을 잘랐다. `.deck-controls`의 오른쪽 경계를 요청 폭에서 18px 안쪽에 두고 자신의 실제 폭만큼 이동하도록 보정했다. 일반 열람 모드에는 적용되지 않는 QA 선택자만 바뀌었으며, 스킬에도 전체 이동 버튼의 경계를 확인하도록 보강했다.

모바일 13개 예시를 각각 실제 390×844 크기의 독립 iframe으로 렌더하고 축소 없이 3개 시트에 담아 전부 확인했다. 최종 CSS에서 오른쪽 이동 버튼·설정·stage 경계가 모두 화면 안에 들어온다. 세로 모바일의 stage 위아래 여백은 16:9 덱의 레터박스다. 초기 잘린 캡처는 최종 증거에서 제외했다.

브라우저 이벤트 검사 85개가 모두 통과했다. 각 화면의 경계·직접 자식 배치·번호·리포트 anchor, 키보드 Home/End·좌우 이동, 이전/다음 버튼, 목차 생성·이동, 설정·테마, 이미지 확대·줌·Esc와 포커스 복귀, KaTeX, 독립 그림·표 번호, Index/Slides/Report 연결을 확인했다. 브라우저 전체화면 전환의 사용자 제스처는 이 자동 검사 범위에 포함하지 않았다.

PDF는 13페이지이며 본문 12페이지 모두 리포트 링크와 현재/전체 번호를 텍스트 추출로 확인했다. 그림·수식·코드·표 페이지를 1280×720으로 래스터화해 확인했다. 데스크톱 제어 UI가 자동으로 숨겨진 뒤에도 footer 번호가 보이는 실제 렌더를 별도로 확인했다.

최종 증거는 `tmp/browser-shots/study-deck-template-20260910/`에 있다. `1366/`, `1600/`은 각 13장, `mobile-sheet-1.png`부터 `mobile-sheet-3.png`는 13개 독립 모바일 화면이다. `deck.pdf`, `pdf-figure.png`, `pdf-08.png`부터 `pdf-10.png`, `idle-footer.png`, `browser-qa-mobile.png`, `browser-qa-result.json`과 검증 로그를 함께 보관했다. `render-evidence.json`에 입력·이미지 해시와 데스크톱 캡처 이후 변경이 해당 viewport에 적용되지 않는 QA 선택자뿐임을 기록했다. 최종 잔여 캡처 manifest 검증은 completed=2, skipped=4, failed=0이다. skipped 파일도 같은 최종 입력의 모바일 시트·PDF로 검증한 뒤 재사용했다.

스킬 개선은 이번에 확인한 공통 화면 요소 누락과 QA 버튼 잘림 검사에 한정했다. 추가 스킬이나 실행 스크립트는 만들지 않았으며, 기존 공개 회차 산출물은 변경하지 않았다.
