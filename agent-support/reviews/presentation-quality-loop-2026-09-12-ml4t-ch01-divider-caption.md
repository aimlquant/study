# ML4T Chapter 1 — 장 구분과 그림 캡션 수정

## 요청과 기준선

사용자가 장 구분 페이지에서 제목보다 숫자만 보이는 형식을 지적하고, 그림 아래의 `그림 N | 제목` 한 줄 캡션을 모두 제거하며 두 사항을 스킬에 반영하도록 요청했다. 기존 발표자료 배포 권한 안에서 같은 URL을 갱신한다.

기준 커밋: `436b14fee02b5989c051cd97fba354698dfe179f`. 공개 페이지 `?v=divider-audit-436b14f#/3`의 1366×768 화면을 직접 확인했다. 제목은 상단에 실제로 보였고, 본문에는 큰 숫자만 떨어져 있었다. **제목이 렌더되지 않는 결함은 재현하지 못했으며**, 구분 장에서 제목과 번호가 분리된 시각 위계를 수정한다.

## 변경

- 구분 장 3/9/19/25/32/37: 원본 제목·순서·좌표를 유지하고 번호와 제목을 중앙의 한 묶음으로 배치한다. 실제 h1은 56px, 번호는 32px이며 설명·리포트 링크·전체 장수는 유지한다.
- 그림 장 8/11/17/21/24/28/29: 일곱 figcaption을 제거한다. 그림, alt, 확대 보기의 식별 제목, 출처 좌표, 리포트 참조를 유지한다. 28번에서 캡션에 있던 사후 국면·연율 변동성 조건은 보이는 본문에 합친다.
- 상세 리포트·발표자 노트·SVG는 변경하지 않는다. 이 요청은 발표자료의 캡션 형식에 적용한다.
- study-presentation 스킬과 절차·디자인·청사진을 수정하고 공용 덱에 같은 구분 장 예시와 캡션 없는 그림 기본값을 반영한다. 과거 회차를 일괄 수정하지 않는다.
- 명시적 `data-figure-captions="none"` 계약에서는 figcaption 재유입을 실패시킨다. 기존 번호형 그림 계약과 데이터 표 번호 검사는 유지한다. 캡션을 숨겨 기존 검사를 통과시키는 방식은 쓰지 않는다.

## 검증과 검토

렌더 위치: `tmp/browser-shots/ch01-divider-20260912/`. 배포 직전 증거와 파일 해시는 동명의 verification JSON에 남긴다. 동일한 관련 HTML/CSS/자산에서 새로 생성한 1600×900·1366×768·390px 렌더만 최종 증거로 인정한다. 상세 리포트는 이전 검토본과 바이트가 같으므로 앞선 리포트/PDF 검증이 유효하다.

전체 저장소 검사: 288 tests, 5 skips(외부 서비스 라이브러리 미설치); 빌드 및 --check 통과. 교재를 연결한 사이트 검사 100 HTML 통과, 기존 외부 iframe 경고 23건. quick_validate.py와 git diff --check 통과.

Claude 검토는 같은 Herdr workspace w8의 기존 `aimlquant-claude`에 요청했으며, 작업 디렉터리·대기 상태·bypass permissions를 확인했다. 검토 요청에는 고정 파일 해시와 검토 문서 소유권을 명시했다. 별도 임시 탭은 만들지 않았다.

## 검토 지적 처리

Claude의 보완 두 건을 모두 채택했다. 29번 lead에 `원서는 … 위험 수치를 보고했습니다`를 넣어 원서 보고값임을 밝혔고, 절차 §2의 캡션 지시는 `리포트 캡션`으로 한정했다. Claude가 새 해시를 확인하고 두 건 모두 해소로 판정한 기록은 [검토 문서](2026-09-12-ml4t-ch01-divider-caption-claude.md)에 있다. 미사용 회차 CSS 한 줄 삭제 제안은 시각적 결함이 없으므로 이번 작업에 넣지 않았다. 후속의 `별도 분석` 낱말 제안도 필수 보완이 아니며, 26번의 첫 분석과 29번의 다른 네 입력 목록이 이미 대비되므로 본문을 다시 바꾸지 않는다.

모바일 실제 화면에서 구분 장 footer의 숫자가 어두운 배경에 묻히는 것을 추가로 확인했다. `.chapter-divider .slide-footer b { color: inherit; }`로 같은 밝은 footer 색을 사용하게 했다. 회차·공용 CSS에 동일 적용하고 여섯 구분 장을 세 크기로 다시 렌더해 확인했다. 그림 슬라이드에는 이 선택자가 적용되지 않는다.

브라우저 오류 화면 세 건은 실제 렌더로 인정하지 않고 재생성했다. 셸에 매인 미리보기 프로세스 종료 후 로컬 전용 지속 서비스로 복구했으며, 긴 manifest 작업도 같은 방식으로 수명만 보존한다. 모든 브라우저는 기존 owner-only runner와 단일 잠금·cgroup을 그대로 거친다. 병렬로 잘못 시작한 후속 manifest는 잠금에서 거절되어 중단했고, 이후에는 직렬로 실행했다.

Claude는 선택한 렌더와 의미·계약을 검토했고 두 보완의 해소를 새 해시로 재확인했다. 최종 footer 색, 템플릿 전수 화면과 공개 페이지 화면은 Codex가 확인했다. 각 검토자의 확인 범위를 합쳐 설명하며, Claude가 모든 최종 렌더를 봤다고 표시하지 않는다. 남은 중대·필수 보완은 없다.

## 배포와 재현 증거

산출물 커밋은 `f68ab466a547a790eef74e7742f38ba6c6fd6d32`이다. 같은 SHA의 Pages 실행 `34656117229`가 성공했고 공개 HTML·CSS·리포트의 SHA-256이 로컬 검토본과 일치했다. 작업 중 별도로 들어온 Webex 일정 수정 `84601a6`은 그대로 보존했다.

스크린샷과 수정 파일의 해시, 변경하지 않은 리포트·노트·그림의 해시, 배포 조회 결과는 [검증 기록](2026-09-12-ml4t-ch01-divider-caption-verification.json)에 있다. 검증 기록의 캡처 경로는 공개 사이트에 복사하지 않은 로컬 QA 증거다. 스킬·절차·템플릿과 이 검토 기록은 후속 커밋으로 저장하며 공개 발표자료의 HTML·CSS를 다시 바꾸지 않는다.
