### 보완 1 — 해결

R1과 현재 덱을 슬라이드 단위로 대조한 결과 **변경된 슬라이드는 17·19·38·51 정확히 넷이고, 슬라이드 밖 공유 HTML은 바이트 동일** 합니다.

- 슬라이드 17은 `r` 을 리포트와 같은 `returns` 로 되돌리고 마지막 줄을 `parts = {"탐색": …, "확인": …}` 로 복원했습니다.
  덱 발췌가 리포트 코드의 부분집합이 되었고, 코드 안에 `탐색`·`확인` 이 등장해 다음 장 표 7의 두 행과 이름으로 연결됩니다.
  lead에 `가이드 코드 발췌 ·` 표시가 붙었습니다.
- 슬라이드 38은 `r = prices.pct_change(fill_method=None).dropna()` 를 발췌 안에 직접 넣고 `# 251행 × 5열` 을 같은 줄에 두었습니다.
  `prices` 에는 `# prices: 앞에서 불러온 동일한 5종목 가격 표` 라는 명시적 생략 표시가 있고,
  lead가 `앞 실습과 달리 종목별 수익률을 평균하지 않습니다` 로 차이를 먼저 말합니다.
- 절차의 코드 발췌 기준을 다시 적용했습니다. 두 발췌 모두 **표시된 변수가 전부 같은 발췌 안에서 바인딩되거나 명시적 생략 표시를 가집니다.**
  더 이상 같은 이름이 두 자료를 가리키지 않으므로 R1이 지적한 지시 불일치가 사라졌습니다.
- `desktop-38.png` 와 `projector-38.png` 에서 11줄 코드가 잘림 없이 읽힙니다.

## 추가 자체 발견 — 공용 템플릿 SVG 대비: 타당하고 수정도 정확합니다

R1의 64개에 없던 세 파일이 이번 기준선에 들어왔습니다. 원인과 효과를 직접 확인했습니다.

- 세 파일 모두 내부 스타일시트에 `.meta { font-size:12px; fill:#6B6B72; … }` 가 있고,
  어두운 상자(`#0F2C59`) 위의 보조 글자에는 `fill="#D9E2EF"` 라는 **presentation attribute** 가 붙어 있었습니다.
  CSS 클래스가 presentation attribute를 이기므로 밝게 지정한 색이 무시되고 짙은 회색으로 그려졌습니다.
- 각 파일에서 바뀐 것은 그 한 노드의 `fill="…"` → `style="fill:…"` 하나뿐입니다. 좌표·문자·구조 변화가 없습니다.

| 파일 | 수정된 텍스트 | 수정 전 대비 | 수정 후 대비 |
| --- | --- | --- | --- |
| concept-flow.svg | 근거 · 승인 · 피드백 | 2.60 : 1 | 10.54 : 1 |
| mechanism-path.svg | 설명 · 사용 · 기록 | 2.60 : 1 | 10.54 : 1 |
| operating-loop.svg | 규칙 · 승인 · 이력 | 2.60 : 1 | 10.54 : 1 |

WCAG AA의 일반 텍스트 기준 4.5 : 1을 **밑돌던 상태에서 크게 웃도는 상태로** 바뀌었습니다.
`template-contrast-operating-loop.png` 실제 크기 렌더에서 어두운 상자의 보조 글자가 또렷하게 읽히고,
같은 그림의 밝은 상자 세 개는 원래의 회색을 유지해 의도한 위계가 보존됩니다.
세 PNG는 SVG 수정 시각 이후에 생성됐고 `template-contrast-baseline.json` 의 해시가 현재 파일 및 R2 기준선과 모두 일치합니다.
회차 SVG·CSS는 R1과 바이트 동일하므로 이번 산출물의 그림에는 영향이 없습니다.

## 이번 라운드의 새 결함

### 보완 A — 리포트 설정 패널의 네 번째 링크가 패널 밖으로 나갑니다

- **위치**: `report.html` 우측 상단 설정 패널의 `이동` 행. 증거는 `report-settings-desktop.png` (1440px)
- **계측**: 패널의 흰 배경은 x = 1156\~1402에서 끝나고(폭 약 246px, 선언값 248px과 일치),
  `회차` 칩의 픽셀은 **x = 1419까지** 이어집니다. 패널 오른쪽 테두리를 **약 17px 넘어섭니다.**
- **원인**: `.report-settings-panel { width: 248px; padding: 14px; }` 이므로 내용 폭은 220px입니다.
  그 안의 `.report-quick-links { display: flex; gap: 6px; }` 에는 **`flex-wrap` 이 없어** 네 칩이 한 줄에 강제로 놓입니다.
  R1까지는 링크가 셋이라 들어갔고, 보완 3으로 `Slides` 가 더해지면서 폭을 넘겼습니다.
- **범위**: 덱 설정 패널은 링크가 셋이라 정상입니다. 덱 51장 상호작용 검사의
  `51 slide layout sweep: no overflow` 는 덱을 훑은 결과이므로 이 결함과 무관하며, 서로 모순되지 않습니다.
- **영향**: 학습 내용에는 영향이 없고 리포트 본문도 정상입니다. 다만 공개 페이지의 상시 노출 요소이고,
  평가표 게이트 5의 “최종 표시 크기에서 잘림·겹침이 없다”에 걸립니다.
- **권장 수정 위치**: 회차 `assets/report.css` 의 `.report-quick-links` 에 `flex-wrap: wrap` 한 줄.
  같은 계약이 공용 템플릿 CSS에도 있으므로 함께 맞추는 편이 재발을 막습니다. 패널 폭을 늘리거나 라벨을 줄이는 대안도 가능합니다.
- **등급 근거**: 이해를 막지 않고 국소적이므로 `보완` 입니다.

### 보완 B — 모바일 설정 메뉴가 미검증입니다

- **위치**: `report-settings-mobile.png` (390px)
- **사실**: 이 캡처는 **설정 패널이 닫힌 상태** 의 리포트 표지를 보여 줍니다. 톱니 아이콘만 있고 패널이 열려 있지 않습니다.
  따라서 390px에서 네 링크가 어떻게 배치되는지에 대한 증거가 없습니다.
- **영향**: 패널 폭은 `min(248px, calc(100vw - 36px))` 로 390px에서도 248px이지만 화면 여백이 좁아,
  보완 A와 같은 돌출이 뷰포트 잘림으로 이어질 수 있습니다. 지금은 좋다고도 나쁘다고도 말할 수 없습니다.
- **권장 조치**: 보완 A를 고친 뒤 **패널이 열린 상태** 의 데스크톱·모바일 캡처를 함께 남깁니다.

## 재사용한 R1 근거와 이번에 다시 확인한 것

R1에서 `충분` 이던 부분은 다음 동일성 근거로 재사용했습니다. 모두 제가 직접 계산했습니다.

- 슬라이드 51장 중 **47장의 HTML이 R1과 바이트 동일** 하고 슬라이드 밖 공유 HTML도 동일합니다.
  `r2-freshness.json` 의 `r1_sha256`·`r2_sha256` 가 보관된 R1 사본 및 현재 파일과 각각 일치합니다.
- 회차 `assets/` 의 CSS·JS·SVG·KaTeX 폰트 **42개가 전부 R1과 바이트 동일** 합니다.
- 리포트 변경은 두 라인(범례 문장, Slides 링크)뿐입니다.

그럼에도 변경이 추적·번호 계약을 깨지 않았는지는 다시 전수 확인했습니다.

- `deck-content.json` 의 `report_sha256`·`deck_sha256` 와 `content.json` 의 `report_sha256` 가 모두 현재 파일과 일치(신선)
- 원자료 10개의 `revision` 은 `d78ed12af8219f21495b1fd7ae2ec601d73cba7f` 그대로
- 덱 51장 상호작용 14항목이 1600px·390px 두 뷰포트에서 모두 PASS
- 덱 PDF 51쪽 960×540pt, 리포트 PDF 34쪽 A4, 빈 페이지 없음

## 발행 준비 판정

**덱 자체는 발행 가능합니다.** R1이 지적한 세 보완과 한 제안이 모두 닫혔고, 그중 하나는 기계 검사와 회귀 사례로 일반화됐습니다.
남은 두 건은 리포트 설정 메뉴 한 곳이며 학습 내용·수치·구조에 영향을 주지 않습니다.

다음 라운드는 **설정 메뉴만 좁게 고치고 그 화면만 재검증** 하면 충분하다고 봅니다.

그 둘이 정상이면 여섯 게이트를 모두 `충분` 으로 판정할 수 있습니다. 코드·범례·원자료 대조를 다시 반복할 필요는 없습니다.

공개 페이지 확인은 이 검토에 포함되지 않았습니다. Pages 배포 뒤의 실서버 확인은 별도 단계입니다.
