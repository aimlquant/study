# 발표자료 품질 향상 루프

## 목적

상세 리포트와 발표자료가 원자료의 학습 좌표와 의미를 충실히 보존하면서도,
원자료를 곁에 두지 않아도 이해되는 독립 학습 자료가 되게 한다. 한 회차에서 발견한
재발 가능한 결함은 `study-presentation` 스킬, 제작 절차, 템플릿 또는 검증기로
일반화하고, 같은 규칙으로 실제 산출물을 다시 만들어 효과를 확인한다.

이 절차는 최대 5라운드다. Codex와 Claude가 모두 충분 판정을 내리면 일찍
종료한다. 5라운드 뒤에도 중대 결함이 남으면 완료로 판정하지 않고 남은 결함과
검증하지 못한 범위를 기록한다.

## 평가 표본과 증거

KG Chapter 1·2·3을 기본 회귀 표본으로 사용한다.

- Chapter 1: 개념 설명과 관계 도식 중심
- Chapter 2: 많은 연속 그림과 Listing이 있는 구조
- Chapter 3: 코드·표·그림·연습문제가 함께 있는 긴 절 구조

각 평가는 다음 원자료와 최종 산출물을 함께 본다.

1. 한국어 원본 해설판과 추출한 절·그림·표·Listing·Example·Box·연습문제 목록
2. `report.html`과 `index.html`, `presentation.toml`, 사용한 SVG·CSS·JS
3. 1600×900·1366×768 덱 렌더, 390px 모바일 렌더
4. 리포트 데스크톱·모바일 렌더와 A4 PDF
5. source-fidelity 검사, 사이트 검증, 테스트 결과

HTML 문자열이나 DOM 구조만으로 시각 품질을 통과시키지 않는다. 렌더 이미지만으로
주장·조건·귀속의 의미 충실성을 통과시키지도 않는다.

렌더 증거는 마지막 관련 HTML·CSS·JavaScript·SVG·폰트·렌더러 변경 이후 생성됐음을
파일 시각, 해시 또는 동일 작업 묶음의 기록으로 확인한다. 신선도를 증명할 수 없으면
다시 렌더한다. 긴 캡처 묶음은 `render-shot-manifest.py`의 재시도와
`--skip-existing` 재개를 사용하되, 재개 전에 기존 출력이 같은 변경 집합에서 만들어진
것인지 확인한다. 브라우저 종료 코드만으로 성공을 판정하지 않는다. 파일 서명, 요청한
viewport 치수와 최소 실내용량을 확인해 빈 화면·부분 파일·잘못된 크기는 다시 렌더한다.
긴 문서의 깊은 fragment처럼 단순 headless screenshot이 반복해서 빈 화면을 만들면,
owner-only safe runner 밖의 raw Chrome이나 Puppeteer로 우회하지 않는다. 동일 URL과
viewport에서 DOM 대상의 위치를 확인하고 `report.js`의 hash 복원 로직이나
보호된 runner를 수정한다. runner 소스를 바꿘다면 재설치·검증한 뒤 다시
렌더한다. 그전까지는 신선한 A4나 전체 페이지 렌더가 증명하는 범위만
인정하고, 해당 fragment는 미검증으로 기록한다.

## 품질 게이트

각 검토자는 아래 여섯 영역을 `충분 / 보완 필요 / 중대 결함`으로 판정하고 근거가
있는 파일·원본 좌표·슬라이드 또는 렌더 화면을 지목한다.

### 1. 원본 구조 충실성

- 장·절·소절과 그림·표·Listing·Example·Box·연습문제의 번호, 정확한 번역 제목,
  순서와 실제 설명 위치가 보존된다.
- 별도 매핑표가 본문 통합을 대신하지 않는다.
- 원본의 반복 도형도 단계·강조·상태 차이가 있으면 그 차이를 보존한다.
- 좌표·제목의 존재만 세지 않고, 각 절에 해당하는 정의·메커니즘 또는 논증 사슬·사례나
  근거·조건 또는 실패 경계가 실제 설명으로 통합됐는지 확인한다.

### 2. 의미와 주장 충실성

- 주장 주체, 강도, 조건, 비교 기준, 시점, 예제의 입력·결과와 한계가 바뀌지 않는다.
- 발표자의 해설·운영 보강·현재 관점은 원자료의 주장과 시각적으로 구분된다.
- alt, 캡션, 본문 설명과 실제 도형이 같은 관계와 방향을 표현한다.

### 3. 독립 문서 완결성

- 원자료를 열지 않아도 핵심 용어, 문제, 메커니즘, 예제, 판단 기준과 한계를
  이해할 수 있다.
- 공개 문서가 제작 프롬프트, 원본 순서 준수 선언, 검증 자랑이나 대응표를
  학습 내용처럼 내세우지 않는다.
- 출처 표시는 정확하되 일반 개념 설명의 흐름을 방해하지 않는다.
- 도입·학습 지도·요약·확인 질문만 읽어도 해당 장의 고유한 문제와 논증 흐름을 식별할
  수 있다. 형제 장에서 주제어만 바꾼 범용 문구는 완결성의 증거가 아니다.

### 4. 학습성과 설명성

- 낯선 용어는 첫 사용 전에 정의되고 구체적 입력에서 결과까지 따라갈 수 있다.
- 도형과 코드는 읽는 순서, 왜 필요한지, 해석 또는 실패 경계를 설명한다.
- 리포트는 단순 목록이 아니라 논리를 연결하고, 덱은 발표자가 설명할 수 있을 만큼
  충분하되 한 화면에 과밀하지 않다.

### 5. 발표·시각 품질

- 한 슬라이드 한 핵심 그림을 기본으로 하며 의도적 비교만 예외로 둔다.
- 최종 표시 크기에서 제목, 본문, 코드, 캡션과 출처가 읽히고 잘림·겹침이 없다.
- 같은 수준의 도형은 공통 그리드와 간격을 사용하고, 화살표는 올바른 면의 경계에
  명확한 shaft와 함께 착지한다.
- 이미지 확대, 키보드 탐색, 코드 언어 표지와 코드 창 표현이 동작한다.

### 6. 추적성과 출판 무결성

- 덱의 모든 주장은 먼저 리포트에 있고 `data-report-refs`가 실제 근거를 가리킨다.
- 원본 절 제목 책임, 필수 그림 커버리지와 source 좌표가 완전하다.
- 링크, 회차 ID, 공개 URL, 자산 경로와 생성 인덱스가 일관된다.
- 필수 테스트·사이트 빌드·검증과 실제 렌더 검사가 모두 통과한다.

## 결함 등급과 수정 위치

- `중대`: 원본 의미 왜곡·누락, 잘못된 귀속, 이해를 막는 설명 공백, 읽을 수 없는
  핵심 화면, 깨진 링크나 추적성. 반드시 다음 라운드 전에 수정한다.
- `보완`: 학습성과 가독성을 실질적으로 낮추지만 핵심 의미를 뒤집지는 않는 결함.
  같은 라운드에서 수정하는 것을 원칙으로 한다.
- `제안`: 취향 차이 또는 효과가 불확실한 개선. 근거와 비용을 비교해 채택 여부를
  명시한다.

재발 가능한 판단 규칙은 간결하게 `SKILL.md`에 둔다. 상세 실행 순서는 제작
절차·디자인 문서에, 반복 가능한 기계 검사는 검증기와 회귀 테스트에 둔다.
한 회차에만 해당하는 내용 오류나 레이아웃은 해당 산출물만 수정한다. 자동 검사가
의미 판단을 가장하게 만들거나 정당한 변형을 막는다면 추가하지 않는다.

## 라운드 절차

### 0. 기준선 고정

작업 트리와 표본 경로를 고정하고 원자료 inventory, 현재 검증 결과와 실제 렌더를
확보한다. 기존 사용자 변경은 별도로 식별해 보존한다.

### 1. 독립 검토

Codex와 Claude는 같은 품질 게이트로 현재 원자료·리포트·덱·렌더를 각각 검토한다.
Claude의 첫 검토에는 Codex의 예상 결함이나 의도한 수정안을 주지 않고 원자료와
산출물, 평가표만 전달한다. 각 지적은 증거 위치, 등급, 영향과 권장 수정 위치를
포함해야 한다.

첫 판정이 끝날 때까지 다른 검토자의 원장과 판정을 읽지 않는다. 도구상 이를 보장할
수 없어 원장을 읽은 뒤 검토했다면 `독립 검토`가 아니라 `독립 재검증`으로 기록하고,
증거를 새로 수집했는지 별도로 밝힌다. 첫 판정 뒤에는 원장을 열어 누락과 이견을
대조한다.

### 2. 합의와 반증

두 검토 결과를 결함 원장으로 합친다. 의견이 다르면 원자료 좌표와 최종 렌더를
근거로 반증한다. 단순 동의 수나 취향으로 결정하지 않는다. 채택·기각·보류와 이유를
각 항목에 남긴다.

### 3. 일반화와 구현

채택한 지적을 `스킬 / 절차·템플릿 / 검증기·테스트 / 회차 산출물`로 나눈다.
리포트를 먼저 수정하고 리포트 게이트를 다시 통과한 뒤 덱을 파생 수정한다.
스킬 문구를 늘렸다면 중복 규칙을 제거하고 quick validation을 실행한다.

### 4. 재생성 및 검증

영향받은 표본을 새 규칙으로 갱신한다. source-fidelity와 전체 저장소 검사를 돌리고,
변경된 덱·리포트·SVG를 요구 viewport와 A4에서 다시 렌더해 실제 픽셀을 검사한다.
한 형제 도형이나 레이아웃에서 결함을 발견하면 같은 유형 전체를 감사한다.
코드 발췌는 표시된 모든 변수가 같은 발췌 안에서 바인딩되는지, 원문 코드를 고쳤다면
실행 보정의 내용과 이유가 독자에게 표시되는지도 확인한다.

### 5. 재평가와 종료 판단

Claude에는 현재 산출물과 이전 라운드에서 채택한 요구사항만 주고 재평가를 요청한다.
Codex도 독립적으로 다시 판정한다. 다음 조건을 모두 만족하면 `상호 충분`이다.

- 두 검토자 모두 여섯 품질 게이트를 전부 `충분`으로 판정
- `중대`와 `보완 필요` 결함이 0개
- 필수 자동 검증과 최종 크기 렌더·A4 검사가 통과
- 수정으로 원본 좌표, 주장 조건, 링크와 추적 메타데이터가 새로 어긋나지 않음

하나라도 만족하지 않으면 다음 라운드로 간다. 동일 지적이 재발하면 문구를 또
추가하기 전에 스킬의 위치, 검증 가능성, 템플릿 기본값과 실제 적용 순서를
재검토한다.

사용자가 peer review 종료를 지시하면 대기 중인 요청에 더 이상 본문을
보내거나 nudge·poll하지 않는다. 해당 요청은 사용자 지시로 종료된 것으로
원장에 기록하고 Codex 자체 여섯 게이트 판정과 peer 기준 면제를 분리해 남긴다.
이 경우 peer 결과를 추론하거나 `상호 충분`으로 표시하지 않는다.

## 라운드 기록 형식

각 품질 루프는 `agent-support/reviews/presentation-quality-loop-YYYY-MM-DD.md`에 영구
원장을 남긴다. 같은 날 여러 루프가 있으면 파일명에 study slug나 session ID를 붙인다.
대화 기록은 보조 자료일 뿐 원장이 아니다. 원장만 읽어도 발견한 결함, 판단 근거,
수정 계층과 실제 파일, 검증 증거, 남은 항목을 복원할 수 있어야 한다.

각 라운드는 아래 항목을 남긴다.

```text
라운드 N / 대상 커밋 또는 작업 트리
Codex 판정 / Claude 판정
증거가 있는 중대·보완·제안 목록
채택·기각·보류와 근거
스킬·절차·검증기·산출물 변경
자동 검증 및 실제 렌더 결과
다음 라운드 진입 이유 또는 상호 충분 종료 근거
```
