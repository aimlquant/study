# Study Presentation

Read `AGENTS.md`, `agent-support/studies.toml`, and `agent-support/procedures/study-presentation.md` completely before editing. For a new session also read `agent-support/templates/STUDY_SESSION_BLUEPRINT.md` and both template `DESIGN.md` files, then scaffold with `agent-support/scripts/new-presentation.py`. The registry resolves active/archive material paths; the public `html/studies/<study-slug>` path never follows that move. Create the paired report and deck unless the user asks for one artifact, and never overwrite an existing session with the scaffolder.

## Checkpoint 1 — source inventory

Audit the raw explainer before authoring. Record every chapter/section, figure, table, listing, example, box, and exercise in source order with its exact translated title, claim owner and strength, conditions, dated demonstrations, examples, and visual relationships. For each section, also record the explanatory payload that makes it learnable: definition, mechanism or reasoning chain, evidence/example, and condition or failure boundary when they exist. Copyright-safe paraphrase may change prose and artwork, not navigational coordinates, explanatory payload, or meaning. Link private material through `../../../../materials/?p=...`; keep the registry-relative path in `source_material`.

## Checkpoint 2 — integrated report

Finish `report.html` before writing session-specific slides. Rebuild the body on the source outline; put every coordinate at its real explanatory position with a stable `id`, `data-source-kind`, and `data-source-ref`. When an explainer source has ordered H2/H3 headings but no printed section numbers, set `source_outline_style = "ordered-headings-v1"` and let the validator derive stable chapter-relative coordinates from source order; do not invent numbering or rewrite heading text merely to satisfy the manifest. A mapping table or a title-only section is not a substitute for the recorded explanatory payload. Keep AIML Quant synthesis visibly outside the source numbering namespace and label it in audience-facing prose; do not blend new operating rules, cautions, or interpretations into the source voice. Preserve conditional claims, precise attribution, and comparison levels; define specialist terms at first use. Use the report's own explanatory voice, with source notes adjacent to source-dependent claims and reconstruction scope.

Make the opening, learning map, summary, and checkpoint questions express this chapter's own problem, argument, and decision path. Do not reuse generic sibling-chapter boilerplate merely because its structure fits. A reader should be able to identify the chapter from those passages without seeing the cover.

Give each source figure coordinate a semantically distinct asset. Repeated mental models must visibly preserve changed state; process and result figures need different visual grammar. A reconstruction may simplify decoration but must retain the source's comparison axes, direction, labels, and state changes. Keep the SVG body to the diagram itself: node identity labels and essential values may remain, but move a redundant title, subtitle, legend, side summary, footer commentary, or added interpretation into the adjacent caption or prose. Label any added gate or interpretation there as AIML Quant synthesis. Never alias one `src` or byte-identical copies under different captions. Label source visuals `그림 N`, not `교재 그림 N`. Mark visuals the deck must carry with `data-deck-use="required"`. The report gate includes complete structure and argument coverage, captions/sources, TOC/lightbox, desktop/mobile render, and inspected A4 PDF. Only then set `source_fidelity = "source-structure-v1"` and `source_material`.

## Checkpoint 3 — report-derived deck

Derive every deck claim, term, table, and visual from the approved report; update the report first if a slide needs new evidence. Keep `data-report-source="report.html"`, valid `data-report-refs`, visible source coordinates, and `data-source-refs`. Assign each source section title to exactly one slide with `data-source-title="section:N.N"`; that slide must show the explainer's exact translated title and also reference the same section. Later slides within the section may use conclusion-style titles.

Use one substantive source figure per slide by default. Keep its exact source coordinate and caption title (the first complete sentence) visible; rewrite later explanatory caption sentences as independent teaching prose instead of copying them into the title. Multiple `figure:` refs require a real simultaneous comparison, final-size legibility, and `data-figure-comparison="intentional"`. A deck image must first exist in the report. If legibility requires a deck-only adaptation, mark it `data-report-visual-adaptation="intentional"`, reference and link the source report figure, and preserve its meaning. Explain how to read a visual, why it matters, and its interpretation/failure boundary in at most three short points; split overflow instead of truncating the title or making type unreadable. All deck images need click/keyboard fullscreen zoom. Every block code sample needs a language marker on `<pre>` or its direct `<code>` and visible code-window chrome.

Keep code excerpts internally readable as executable units. Every displayed variable must be bound in the same excerpt by its relevant `LOAD`, `MATCH`, `WITH`, function signature, or an explicit omission marker. Preserve source code by default; when correcting a source typo or changing a query for execution, label the correction beside the listing and state what changed instead of silently presenting it as the source listing.

## Checkpoint 4 — independent publication

Remove prompts, scaffold/blueprint language, pipeline diagrams, compliance claims, and statements about following source order from audience-facing artifacts. Covers, overviews, TOC text, summaries, and takeaways must teach the subject itself. Re-audit the paired report and every slide after either changes so conditions, attribution, IDs, visible labels, and trace metadata cannot drift.

## Checkpoint 5 — migration and completion

Before replacing or deleting an existing artifact, inventory official, retained, and duplicate outputs plus all public links. When the user explicitly retires a derivative, preserve the immutable session ID/page URL, recover or deliberately discard any unique useful assets, remove artifact directories and registry links together, rebuild generated pages, and check broken links. Never infer permission to delete an unregistered sibling artifact. A public SVG that remains unreferenced must be listed in `presentation.toml` under `[[retained_unreferenced_assets]]` with its path and a concrete retention reason; remove that record when the asset becomes referenced, and never use the record as implicit deletion approval. Likewise, every session-root HTML file other than canonical `index.html` and `report.html` must be removed with explicit user approval or registered under `[[retained_alternate_html]]` with a concrete reason and canonical-entry explanation.

Run the repository's complete required verification, render the deck at 1600×900 and 1366×768 plus 390px mobile, and inspect the report at desktop/mobile/A4. In a fixed-size scaled deck, size slide content in stage coordinates: do not use viewport-relative `vh`/`vw` units for images, diagrams, tables, or other content whose fit must remain inside the slide. When such a defect is found, search the whole deck for the same unit or layout pattern and render every affected sibling. Regenerate or prove freshness of the render set after the last relevant HTML, CSS, JavaScript, SVG, font, or renderer change; filenames from an older batch are not visual evidence. A successful browser exit code is also not enough: reject a missing signature, wrong viewport dimensions, or implausibly empty capture before resuming or claiming visual coverage. Use the manifest driver's bounded retries and final failure summary, and use `--skip-existing` only when every retained output belongs to the same post-change batch. Never bypass the owner-only safe runner with raw Chrome or Puppeteer; for persistent deep-fragment blanks, first use the report template's opt-in `?fragment-capture=1#<section-id>` QA layout, which removes only preceding report siblings and leaves ordinary reader hash links unchanged. If that mode also fails, fix hash restoration or the guarded runner, reinstall and verify the runner if its source changed, and regenerate. Treat per-session CSS as a snapshot with intentional labels, but keep shared template contracts synchronized: Korean font stack and wrapping, print section starts, and heading page integrity. In particular, render the longest report-cover title at 390px and reject a session snapshot that restores `white-space: nowrap` or clips the title even when the shared template is already correct. Give every marker-ended SVG connector path an explicit `fill:none`; visually audit sibling SVGs after any connector defect. SVG text cannot rely on KaTeX processing: use Unicode symbols or plain text inside SVGs and keep full formulas in adjacent HTML captions or prose. Inspect A4 text extraction or page rasters for headings split across pages. Source-fidelity decks may exceed the normal 18–30-slide guideline when one-figure-per-slide and complete learning-coordinate coverage require it. For iterative quality work, follow `agent-support/procedures/presentation-quality-loop.md` and keep its durable round ledger under `agent-support/reviews/`; future sessions must be able to recover the observed defect, decision, changed layer, affected files, and proof without relying on chat history. Use peer review for explanatory-payload coverage, semantic visual fidelity, claim ownership, beginner friendliness, and audience-facing prose; string checks do not decide those qualities. If the user ends peer review, stop further sends and nudges, record a Codex-only six-gate verdict plus the waived peer criterion, and never label the result mutually sufficient.

At minimum, after creating or editing a report or deck, run:

```bash
python3 agent-support/scripts/build_site.py
python3 agent-support/scripts/build_site.py --check
python3 agent-support/scripts/validate-site.py --site html
```

Inspect actual pixels; DOM and CSS declarations alone do not prove legibility. Preserve user changes. Commit, push, PR, or change Pages only when the user requested that scope.
