# Study Presentation

Read `AGENTS.md`, `agent-support/studies.toml`, and `agent-support/procedures/study-presentation.md` completely before editing. For a new session also read `agent-support/templates/STUDY_SESSION_BLUEPRINT.md` and both template `DESIGN.md` files, then scaffold with `agent-support/scripts/new-presentation.py`. The registry resolves active/archive material paths; the public `html/studies/<study-slug>` path never follows that move. Create the paired report and deck unless the user asks for one artifact, and never overwrite an existing session with the scaffolder.

## Checkpoint 1 — source inventory

Create a textbook-faithful, independently understandable learning report, with no talk-length or slide-count limit on its explanatory depth. Read the original chapter alongside its translation, explainer, errata and executable materials; the explainer is a reading aid, not the authority over the original. Audit these sources before authoring. Record every chapter/section, figure, table, listing, example, box, and exercise in source order with its exact translated title, claim owner and strength, conditions, dated demonstrations, examples, and visual relationships. For each section, also record the explanatory payload that makes it learnable: definition, mechanism or reasoning chain, evidence/example, and condition or failure boundary when they exist. For executable material, inventory the complete evidence chain as one unit: notebook or source cell, input and target, code, recorded chart/table/text output, metric and unit, split or period, and the report location that will interpret it. Do not leave an available recorded output behind, and do not invent an output when the source has none. Copyright-safe paraphrase may change prose and artwork, not navigational coordinates, explanatory payload, or meaning. Link private material through `../../../../materials/?p=...`; keep the registry-relative path in `source_material`.

## Checkpoint 2 — integrated report

Finish `report.html` before writing session-specific slides. Rebuild the body on the source outline; put every coordinate at its real explanatory position with a stable `id`, `data-source-kind`, and `data-source-ref`. When an explainer source has ordered H2/H3 headings but no printed section numbers, set `source_outline_style = "ordered-headings-v1"` and let the validator derive stable chapter-relative coordinates from source order; do not invent numbering or rewrite heading text merely to satisfy the manifest. A mapping table or a title-only section is not a substitute for the recorded explanatory payload. Keep AIML Quant synthesis visibly outside the source numbering namespace and label it in audience-facing prose; do not blend new operating rules, cautions, or interpretations into the source voice. Preserve conditional claims, precise attribution, and comparison levels; define specialist terms at first use. When a recomputed value differs from the value printed in the source, record both and label which one each figure shows; a correct recomputation still does not silently replace a printed value. Use the report's own explanatory voice, with source notes adjacent to source-dependent claims and reconstruction scope.

Explain; do not merely cover (도라 msg 16175, 2026-11-01). Use the Korean explainer (`*_ko_explained.md`) as the prose skeleton: follow its section order and its explanations, and verify every fact, number and condition against the original and translation. The report may be longer than the explainer; there is no length cap. Every source passage must be explained, not named: when a source sentence lists several concepts, mechanisms or conditions, give each one its own sentences or paragraph — what it is, why it matters here, and a concrete example or small number — instead of compressing them into a noun-phrase list or a dense table cell. Write flowing Korean prose: open each paragraph from the question the previous one raised, give the example or intuition before the formal definition, explain an unfamiliar term at its first use in plain words, and keep tables for genuine field-by-field comparison rather than as a substitute for explanation. Keep source and reconstruction notes to one short trailing line near the asset; they must never be the reader's first or main sentence.

Rich explanatory visuals (도라 msg 16191): explain concepts, procedures, comparisons, timelines and causal claims visually beside their prose, using purpose-built SVG diagrams, flows, timelines, comparisons or small worked calculations. Keep every source figure coordinate; label additional figures as `AIML Quant 도해` without giving them invented source coordinates. New sessions default to `figure_density = "rich-v1"`; for those sessions, each source H2 section requires at least two distinct explanatory SVG figures, and each explanatory H3 unit requires at least one between its heading and the next H3. A reference-only H3 may carry a concrete `data-visual-exempt` reason; never exempt a concept merely to pass. Local SVGs must contain text and at least two visible shapes, and repeated bytes cannot fill the quota. Figure counts are a minimum; peer review still checks meaning. Run `validate-site.py` and the bbox gate described in the procedure. Existing sessions retain their existing contract. The scaffolder permits `--figure-density none` to omit this gate.

Make the opening, learning map, summary, and checkpoint questions express this chapter's own problem, argument, and decision path. Do not reuse generic sibling-chapter boilerplate merely because its structure fits. A reader should be able to identify the chapter from those passages without seeing the cover. A checkpoint question is a claim too: its premise must be answerable from the artifact that asks it and must rest on evidence the report actually states, not on a source passage the report left out.

Teach an unfamiliar algorithm or statistical procedure in the order a beginner must reason through it: the question it answers, a visual input-to-output or worked example, the mechanism, the smallest readable code excerpt, the recorded execution result, and the interpretation plus failure boundary. A code block is not complete evidence by itself. When a notebook contains the experiment, pair the excerpt with its chart or table and state what the output measures. Explain displayed formulas in nearby prose: define the output and every symbol, expand abbreviations and units at first use, and give a small numerical reading when the symbols remain abstract. Distinguish prediction accuracy, return, risk-adjusted return, and cost-adjusted return instead of presenting them as interchangeable performance scores.

For quantitative experiments, make the comparison contract explicit: target horizon, feature timing, training/test or chronological validation boundary, position delay, holding period, overlapping-exposure normalization, transaction-cost convention, and whether a number is in-sample or out-of-sample. Move from a coefficient or statistic to interpretation one rung at a time — mathematical sign or value, model prediction, then a cautiously labelled economic hypothesis — and never promote association into causation. Put an empirical observation and a theoretical argument in separate sentences when they point in different directions.

Write Python-first adaptations in the target runtime's vocabulary. Remove source-language API names and migration narration such as MATLAB parameter mappings unless the difference changes the reproduced result or prevents a correct interpretation. If it matters, explain it once in ordinary body prose beside the affected result, not as a code-window caption. Avoid repeated provenance boilerplate such as `AIML Quant 재구성`, `AIML Quant 재현 코드다`, or `여기서 원본과 갈라진다`; preserve provenance with a concise nearby source note and reserve a visible `AIML Quant 보충` label for genuinely added interpretation or operating guidance.

Give each source figure coordinate a semantically distinct asset. Repeated mental models must visibly preserve changed state; process and result figures need different visual grammar. A reconstruction may simplify decoration but must retain the source's comparison axes, direction, labels, and state changes. Keep the SVG body to the diagram itself, split by whether text decodes the figure or describes it. Decode text stays, because a slide reusing the image still needs it: axis and tick labels, chart legends, node identity labels, data-point and event labels, and the numbers inside a diagram cell. Describing text moves out: a title or subtitle, footer commentary, a summary or result panel laid over the plot, a side explanation panel, a conclusion, and the explanatory tail of a `label — explanation` pair. Five shapes evade a casual read and have all shipped before — a single-line title at body font size rather than a heading, a callout in the middle of the diagram rather than at an edge, that `label — explanation` tail, a result box floating over the chart area, and a right-hand explanation panel. Before moving any of it, search the whole surrounding section rather than the figure block alone: a well-written report almost always says it already, so the default is to delete, not to move. This rule is gated, not advisory — `validate-site.py` rejects text outside every shape, and stacked runs sharing one x, at 28 characters or more, and `agent-support/reviews/svg-prose-baseline.json` grandfathers only what already shipped; drop entries as sessions are cleaned and never add one for new work. Label any added gate or interpretation there as AIML Quant synthesis. Never alias one `src` or byte-identical copies under different captions. Label source visuals `그림 N`, not `교재 그림 N`. Mark visuals the deck must carry with `data-deck-use="required"`. The report gate includes complete structure and argument coverage, captions/sources, TOC/lightbox, desktop/mobile render, and inspected A4 PDF. Set `source_fidelity = "source-structure-v1"` and `source_material` at scaffolding time, not after declaring completion. For a report-only request use `--artifacts report`. New reports use `report_quality = "source-learning-v1"` and a `content_review` record as described in the procedure; report checks run independently of deck checks. Structural validation does not establish semantic fidelity.

### Source-complete visuals and mathematics · visual-math-v1

A detailed report must support study without opening the textbook. Preserve every original figure, chart and table and its original `그림 N`/`표 N` coordinate. In the public repository redraw rather than attach original images: retain structure, axes, legend, labels, values and information. Recompute from available code/data with recorded conditions; otherwise use source-read values and write `원본 판독값` in the caption. A shorter saved time range is not a substitute for the complete source chart. Keep extra explanatory diagrams.

Inventory every original/explainer math occurrence, derivation and transformation within the authored section range, with input hashes and exact source offsets. Preserve original equation numbers. Each equation must explain what it computes, every symbol/unit and a small numerical example. Identical equations from both sources may map to one report equation; retain both source coordinates without forcing duplicate printing. Bare symbols require explicit classification; unrelated example equations cannot compensate for a missing source equation. When a concept needs a defining formula that the source states only in words, add it as an explanatory addition without inventing a source equation number (for example, conditional distribution and rank IC in ML4T 3rd edition Chapter 8, §8.1).

New sessions default to `source_completeness="visual-math-v1"` and a colocated `source-inventory.json` skeleton; `--no-source-completeness` omits that gate. Existing inventory paths under agent-support/reviews remain supported. Run validate-site for coordinate-set equality, source hashes, all math occurrence mappings, equation numbers and explanation anchors; then run the DOM-only KaTeX gate and inspect A4 PDF. Counts are a floor: independent review checks information fidelity and whether a reader can explain the claim, timing, every diagram label, calculation/example and failure condition without the textbook. Apply only inside the declared authored range; never mark unwritten sections complete.

## Checkpoint 2b — reader and Korean gates

Before writing the deck, run two gates on the finished report and record both under `agent-support/reviews/<session>-reader-check.md`.

1. First-time reader check. A reviewer who did not write the report reads the whole report as a study member seeing the chapter for the first time and lists every blocking passage as `location | sentence | why (unknown term · missing example · broken link to the previous paragraph · overcrowded · mentioned but not explained) | minimal fix`. Fix only the listed places without changing the source order or coverage, reread them, and close the gate at zero blocking passages. A self-reread by the author is recorded as a self-check, not as this gate; any part the independent reviewer did not read stays open.
2. Korean naturalness gate. Review the report against `fde-course/working/production/templates/korean-review-corpus.md` (v0.6 or later): its repeated patterns, sentence principles and judging method. Record each flagged sentence with its rewrite. When the same pattern appears in two or more sections, search and fix it across the whole report. Apply the same gate to every visible deck text before publication. Where that corpus is not readable (it lives outside this repository), apply its core principles directly: one meaning per sentence, subject and predicate that agree, verbs instead of stacked noun phrases, no translationese, no repeated sentence endings or nouns, and every unfamiliar term explained where it first appears; record that the fallback was used.
3. After the deck is complete, run the same independent first-time reader check on the whole main deck with the same five reasons, record it in the same file, and keep any slides the independent reviewer did not read open.

## Checkpoint 3 — report-derived deck

Use `agent-support/templates/study-deck/index.html` and its `DESIGN.md` as the canonical presentation format, with the shared CSS/JS copied by the scaffolder. Copy complete example sections and assign unique IDs; choose the content, order and slide count from the reviewed report. For every non-cover slide, preserve the `.slide--teaching` shell in this direct-child order: `.slide-header` (brand and `.section-tag`), `h1`, `.lead`, `.slide-body`, `.takeaway`, `.slide-footer`. Keep the takeaway outside the body, and keep a valid report-anchor link plus `[data-slide-number] / [data-slide-total]` in each footer, including opening and closing slides. Select rows, columns, side-by-side or wide figures, formulas, code and tables from the template examples instead of rebuilding the common shell. Split dense content across complete slides rather than removing the header/footer. The template is a layout library, not a fixed chapter outline.

For a deck derived from an already published report, first audit its figure requirements and notebook evidence; report-only publication does not establish deck coverage. Start from every report figure and table, not only the author-selected `data-deck-use` subset; record its actual slide use or a content-based omission reason before marking required visuals. Build teaching units from the report before choosing slide count: record the question, necessary definition/mechanism, concrete evidence, condition, and actual teaching slides. A divider or a valid reference is not evidence of explanation. Preserve this reasoning across consecutive screens; do not replace it with repeated title/lead/takeaway slogans or move essential meaning only into presenter notes. Read the slides without narration to test whether the inference can be followed. The procedure's report-teaching-v1 review contract records coverage and freshness; neither word counts nor structural checks decide understanding.

Derive every deck claim, term, table, and visual from the approved report; update the report first if a slide needs new evidence. Keep `data-report-source="report.html"`, valid `data-report-refs`, concise visible source coordinates, and `data-source-refs`. Assign each source section title to exactly one slide with `data-source-title="section:N.N"`; that slide must show the explainer's exact translated title and also reference the same section. Later slides within the section may use conclusion-style titles. Use a dedicated divider at each chapter or main-section transition. Group its section number and exact translated title together in the central reading area, with the title as the main visual element; a small heading at the top and a lone oversized number in the body do not satisfy this format. Keep a real, visible `h1`, and inspect every divider, including the longest title, at final desktop and mobile size. For AIML Quant slides, omit the one-row caption band below each figure: do not add a separate `그림 N | 제목` table, strip, or visible `figcaption`. Set `data-figure-captions="none"` on main; keep figure identity in meaningful alt text and optional `data-deck-figure-title`, and preserve visible source/report links. Keep the reading guidance, evidence, units, attribution and limitations in editable slide text rather than deleting them with the caption. This presentation preference does not remove report captions or actual data tables. Keep `data-caption-scope="deck"` and number actual table captions independently in deck order with `data-deck-caption="table"`. If the user explicitly requests numbered figure captions, omit the caption-free policy and use consecutive deck-local `data-deck-caption="figure"` labels. A numbered report-ref link always uses the target report's number.

Use one substantive source figure per slide by default. Keep its exact source coordinate as concise source metadata and preserve the caption title's meaning; rewrite later explanatory caption sentences as independent teaching prose instead of copying them into the title. Multiple `figure:` refs require a real simultaneous comparison, final-size legibility, and `data-figure-comparison="intentional"`. A deck image must first exist in the report. If legibility requires a deck-only adaptation, mark it `data-report-visual-adaptation="intentional"`, reference and link the source report figure, and preserve its meaning. Explain how to read the visual, the concrete observation or mechanism it supports, and its interpretation boundary in visible teaching prose. Put this beside the visual or on explicitly connected consecutive slides; a caption with only a title and source does not suffice. Split overflow instead of deleting the reasoning or making type unreadable. The slide title and nearby prose identify and decode the visual; paragraph-length interpretation belongs in the slide body or another slide. Clearly distinguish a measured output from a conceptual schematic, and ensure every visual claim in the prose or caption is actually encoded in the shapes, arrows, line weights, axes, or legend. All deck images need click/keyboard fullscreen zoom. Every block code sample needs a language marker on `<pre>` or its direct `<code>` and visible code-window chrome.

Keep code excerpts internally readable as executable units. Every displayed variable must be bound in the same excerpt by its relevant `LOAD`, `MATCH`, `WITH`, function signature, or an explicit omission marker. Preserve source code by default; when correcting a source typo or changing a query for execution, label the correction beside the listing and state what changed instead of silently presenting it as the source listing.

## Checkpoint 4 — independent publication

Remove prompts, scaffold/blueprint language, pipeline diagrams, compliance claims, statements about following source order, slide-count rationale, default/appendix operating instructions, and peer-review or authoring deliberation from audience-facing artifacts. Covers, overviews, TOC text, summaries, captions, and takeaways must teach the subject itself. Prefer literal Korean that names the operation or result; do not make an undefined metaphor such as `흔든다`, `무너진다`, `긴장`, or `책임의 이동` carry the main technical claim. Re-audit the paired report and every slide after either changes so conditions, attribution, IDs, visible labels, and trace metadata cannot drift.

## Checkpoint 5 — migration and completion

Before replacing or deleting an existing artifact, inventory official, retained, and duplicate outputs plus all public links. When the user explicitly retires a derivative, preserve the immutable session ID/page URL, recover or deliberately discard any unique useful assets, remove artifact directories and registry links together, rebuild generated pages, and check broken links. Never infer permission to delete an unregistered sibling artifact. A public SVG that remains unreferenced must be listed in `presentation.toml` under `[[retained_unreferenced_assets]]` with its path and a concrete retention reason; remove that record when the asset becomes referenced, and never use the record as implicit deletion approval. Likewise, every session-root HTML file other than canonical `index.html` and `report.html` must be removed with explicit user approval or registered under `[[retained_alternate_html]]` with a concrete reason and canonical-entry explanation.

Run the repository's complete required verification, render the deck at 1600×900 and 1366×768 plus 390px mobile, and inspect the report at desktop/mobile/A4. In a fixed-size scaled deck, size slide content in stage coordinates: do not use viewport-relative `vh`/`vw` units for images, diagrams, tables, or other content whose fit must remain inside the slide. When such a defect is found, search the whole deck for the same unit or layout pattern and render every affected sibling. Visual fit is two-sided: reject both overflow and a primary figure that remains needlessly small while unexplained empty space dominates the available body. Judge the smallest labels at the ordinary slide view rather than treating fullscreen zoom as a substitute, and use separate size contracts for figure-only, tall-chart, and figure-with-table layouts instead of scattered one-off caps. Within a mixed figure-and-table family, account for the asset aspect ratio: a portrait or near-square figure may need a side-by-side contract while a wide chart remains stacked, rather than forcing both through one height cap. Treat contact sheets as coverage maps, not legibility proof: inspect the reported slide and at least one representative of every affected layout family at the capture's original resolution. In fixed-stage mobile captures, distinguish expected viewport letterboxing outside the stage from unexplained whitespace inside the slide before changing layout. Chromium may keep a 500px internal layout viewport even when the guarded runner emits a 390px PNG; if the right edge or settings control is missing, treat the capture as invalid and recapture with the template's opt-in `?qa-width=390` contract instead of accepting the cropped bitmap. Inspect the complete navigation control too: QA placement that assumes a fixed button/counter width can still crop its right edge. For report fragments combine it as `?fragment-capture=1&qa-width=390#<section-id>`. Regenerate or prove freshness of the render set after the last relevant HTML, CSS, JavaScript, SVG, font, or renderer change; filenames from an older batch are not visual evidence. A successful browser exit code is also not enough: reject a missing signature, wrong viewport dimensions, or implausibly empty capture before resuming or claiming visual coverage. Use the manifest driver's bounded retries and final failure summary, and use `--skip-existing` only when every retained output belongs to the same post-change batch. Never bypass the owner-only safe runner with raw Chrome or Puppeteer; for persistent deep-fragment blanks, first use the report template's opt-in `?fragment-capture=1#<section-id>` QA layout, which removes only preceding report siblings and leaves ordinary reader hash links unchanged. If that mode also fails, fix hash restoration or the guarded runner, reinstall and verify the runner if its source changed, and regenerate. Treat per-session CSS as a snapshot with intentional labels, but keep shared template contracts synchronized: Korean font stack and wrapping, print section starts, and heading page integrity. In particular, render the longest report-cover title at 390px and reject a session snapshot that restores `white-space: nowrap` or clips the title even when the shared template is already correct. Give every marker-ended SVG connector path an explicit `fill:none`; visually audit sibling SVGs after any connector defect. SVG text cannot rely on KaTeX processing: use Unicode symbols or plain text inside SVGs and keep full formulas in adjacent HTML captions or prose. Judge each label at its final rendered size rather than in the source, because a present glyph can still be unreadable: a Unicode subscript such as `p₊` collapses to a bare dot at 10.5px, so give it a sized `tspan` instead. Inspect A4 text extraction or page rasters for headings split across pages. When deployment is requested, do not equate an Actions success with a verified live page: match the Pages run head SHA to the merged main commit, wait for the deployment to complete, then render and inspect the exact public deep link with a cache-busting query placed before `#`; cover the reported slide and representative layout families at desktop and mobile. Determine slide count from complete teaching units and final-size legibility. Budget talk time by the explanation each screen needs; slide count is neither an upper bound nor evidence of understanding. For iterative quality work, follow `agent-support/procedures/presentation-quality-loop.md` and keep its durable round ledger under `agent-support/reviews/`; future sessions must be able to recover the observed defect, decision, changed layer, affected files, and proof without relying on chat history. Use peer review for explanatory-payload coverage, semantic visual fidelity, claim ownership, beginner friendliness, and audience-facing prose; string checks do not decide those qualities. If the user ends peer review, stop further sends and nudges, record a Codex-only six-gate verdict plus the waived peer criterion, and never label the result mutually sufficient.

At minimum, after creating or editing a report or deck, run:

```bash
python3 agent-support/scripts/build_site.py
python3 agent-support/scripts/build_site.py --check
python3 agent-support/scripts/validate-site.py --site html --check-materials
```

For shared-template edits, generate a paired session into a temporary `--site` directory so report and deck assets are merged by the real scaffolder. Run `test_presentation_template.py` and render every example at desktop and mobile sizes; verify the shell, report links and page numbers in the generated output. Inspect actual pixels; DOM and CSS declarations alone do not prove legibility. Preserve user changes. Commit, push, PR, or change Pages only when the user requested that scope.

Narrow DOM-geometry exception: only `agent-support/scripts/check-svg-bboxes.mjs` may use Puppeteer for SVG text bounding boxes and local KaTeX DOM checks (parse errors, unrendered delimiters, zero-size equations/radicals), with no screenshot, PDF or video. On the owner's h1 machine, run it through `h1-run --mem 4G --timeout 120`, after the installed safe runner `--check`; the script enforces a 90-second browser deadline and closes its browser in `finally`. On machines without `h1-run` and the owner runner, do not run this script or substitute raw Chrome; inspect the final-size render manually for overlapping text and broken equations and record that manual check. All other raw Chrome/Puppeteer bypasses remain forbidden; actual captures and PDFs always use the owner-installed safe runner.

모든 원본/해설판 Markdown 이미지 발생(링크로 감싼 썸네일 포함)을 원장 images에 offset/path/classification/report_id로 기록한다. correspondence는 실제 시각자료에 연결한다. 캡션 없는 이미지도 생략하지 않는다. duplicate/table-image는 대응 대상과 이유, decoration은 구체적인 이유를 기록하고 짝이 확인한다. 캡션 집합만 맞아도 이미지 발생이 빠지면 실패한다.

### 부분 집필 게시와 새 회차 시작

새 회차는 도해·원본충실도 관문이 기본이다. 원장·검토를 채우기 전 main에 push하면 CI가 실패하므로 작업 브랜치에서 집필한다. 골격의 빈 scope/sources는 자료 없는 CI에서도 실패한다. 완성한 원장은 CI에서 본문 대응·해시형식·경로를 검사하고, materials가 없으면 원본 파일 해시 대조·이미지/수식 재추출만 경고로 생략한다. materials가 있으면 모두 대조하며 --check-materials의 존재 요구도 유지한다. 수동/의미 검토를 자동 통과로 표시하지 않는다.

부분 게시에는 `report_scope={version="sections-v1",sections=["8.1"],include_intro=true}`처럼 실제 집필 절을 선언한다. 교재의 실제 순서에서 해당 절에 속한 그림·표·박스까지 전부 검사한다. 본문 section 집합/순서·content_review.scope·원장 scope와 include_intro가 같아야 하며, report-scope-notice라는 id의 가시 문구로 공개 절과 '작성 중'을 밝힌다. 선언하지 않은 회차는 종전 전체 범위 계약이다. 도입 포함 시 content_review.introduction에 실제 도입 id와 검토 explanation을 기록한다. 미집필 절의 검토를 채우거나 제목만 넣어 통과시키지 않는다.
