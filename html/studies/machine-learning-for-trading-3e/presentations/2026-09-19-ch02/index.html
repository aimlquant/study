데이터는 전략의 원재료이자 첫 번째 위험 요소입니다

머신러닝 알고리즘 이전에 데이터 파이프라인의 조용한 결함을 먼저 잡아야 합니다.

1. 분류와 내재 규칙

데이터는 단순 숫자가 아닙니다. 타임스탬프, 캘린더, 기업행위, 수정 규칙이 결합된 계약입니다.

2. 자산군별 시장 구조

주식의 NBBO, 선물의 롤오버, 옵션의 표면, 크립토의 AMM 슬리피지까지 시장마다 가격 정의가 다릅니다.

3. 가짜 알파의 원천 봉쇄

시점 기준(PIT) 오류, 생존자 편향, 기업행위 왜곡을 소싱 및 저장 단계에서 사전에 차단합니다.

머신러닝 트레이딩 실패의 대부분은 알고리즘이 아닌 데이터 파이프라인의 조용한 결함에서 발생합니다.

왜 프로세스가 모델보다 중요한가

과거 데이터에서 발견한 높은 수익률이 미래에도 이어지려면 엄격한 데이터 엔지니어링이 선행되어야 합니다.

당시 알 수 있었는가?

공시 지연(Lag)이나 나중에 수정된 수치를 과거 의사결정에 소급 투입하면 치명적인 미래정보 누수가 발생합니다.

살아남은 자만의 결과인가?

오늘 상장된 종목만으로 과거를 구성하면 파산·상장폐지된 기업의 손실이 누락되어 성과가 왜곡됩니다.

실제로 거래 가능한 가격인가?

액면분할 미조정, 선물 만기 단절, OTC 참고 호가를 실체결가로 오인하면 가짜 알파가 생성됩니다.

체계적인 데이터 관리 규율이 모델의 정교함보다 장기적 생존을 좌우합니다.

2장의 4단계 논리 로드맵

데이터 정의부터 자산군 구조, 위험 통제, 저장소 아키텍처로 이어지는 4단계 흐름입니다.

§2.1 · 현대적 데이터 분류 체계

시장·펀더멘털·대체 데이터의 본질과 모델링 전 고정해야 할 4대 데이터 계약을 확립합니다.

§2.2 · 자산군별 시장 데이터 환경

주식, ETP, 선물, 옵션, 크립토, 채권 등 9개 자산군의 상이한 시장 메커니즘과 실패 모드를 대조합니다.

§2.3 · 데이터 소싱 실사 프레임워크

5차원 품질 관리, 4대 치명적 실패(PIT, 생존자 편향, 기업행위, 식별자), 벤더 실사 체크리스트를 점검합니다.

§2.4 · 데이터 저장 아키텍처

Parquet 파일 벤치마크, DuckDB/Polars 임베디드 분석, 시계열 DB 및 ASOF 조인 성능을 비교합니다.

이론과 함께 22개 공식 주피터 노트북의 실측 결과를 연계하여 확인합니다.

AIML Quant§2.1 데이터 계약

모델링 전 확정해야 할 4대 데이터 계약

하위 파이프라인 코드가 제각기 해석하지 못하도록 전사적으로 고정해야 하는 원칙입니다.

1. 타임스탬프 의미론

Event Time(사건 발생) vs Knowledge Time(공시 접수) vs Ingestion Time(수집)을 엄격히 분리.

2. 기업행위 조정 방법

분할/배당 요인의 소급 역방향(Backward) 적용 방식 및 총수익률(Total Return) vs 가격수익률 명시.

3. 식별자 안정성

티커 재사용 및 합병에 흔들리지 않는 영구 고유 식별자(FIGI, CIK, PermID) 매핑 체계 유지.

4. 수정 및 재작성 처리

거시지표나 재무제표 개정 시 의사결정 당시의 원본 수치(Vintage)를 복원할 수 있는 이중시간 지원.

이 4대 계약이 누락되면 이후 단계의 특징 추출과 백테스트 전체가 조용히 왜곡됩니다.

AIML Quant§2.2.1 주식

주식: 기업행위 왜곡과 역방향 조정 알고리즘

액면분할과 현금배당은 가격 시계열에 급격한 불연속을 만들어냅니다.

원시 가격의 치명적 오류

7:1 액면분할 시 원시 가격은 -86% 폭락으로 기록되어 모델에 잘못된 매도 신호와 인공 변동성을 학습시킵니다.

역방향 조정 (Backward Adjustment)

현재 가격을 기준으로 과거 가격을 소급 할인하여 경제적 수익률을 보존합니다.

\(P_{\text{adj}, t} = P_t \times \prod_{t < t_s} \frac{1}{\text{split}} \times \prod_{t < t_d} \left(1 - \frac{D_t}{P_{t-1}}\right)\)

장기 백테스트와 ML 특징 공학에서는 반드시 총수익률 기준 역방향 조정을 적용해야 합니다.

AIML Quant§2.2.2 ETP

상장거래상품(ETP)의 이중 구조와 5대 위험

거래소 상장 래퍼와 기초자산 보유층 사이의 불일치를 이해해야 합니다.

ETP의 2대 데이터 계층

시장 거래층: 거래소에서 실시간 형성되는 호가·체결.

기초 보유층: 일말 기준 산출되는 순자산가치(NAV) 및 바스켓 비중.

5대 실패 모드 (Failure Modes)

1. 분배금 재투자 미반영에 따른 수익률 왜곡

2. 위기 시 시장 거래가와 NAV 간의 괴리

3. 유동성 불일치 (유동적 ETF 뒤 비유동 기초자산)

4. 룩스루 누수 (미래의 보유 비중을 과거에 적용)

ETP 분석 시 시장 가격과 NAV 수익률을 명확히 구분하고 보유 비중의 PIT를 통제해야 합니다.

AIML Quant§2.2.3 선물

선물: 만기 롤오버와 연속 시계열 구성

영구 티커가 없는 선물 계약들을 경제적 손익을 보존하는 단일 시계열로 결합합니다.

2대 연속화 방법론

비율 조정 (Ratio): 과거 가격에 비율을 곱해 백분율 수익률(PnL Ratio)을 완벽 보존 (ML 표준 권장).

차분 조정 (Difference): 절대 스프레드를 가감해 달러 PnL 보존 (단, 과거 가격 음수 위험).

담보 이자 수익률 (Collateral)

선물 연속 시계열은 현물 지수와 달리 담보 이자가 제외된 초과 수익률(Excess Return) 대용치로 작동하므로 모델링 시 명시해야 합니다.

롤오버 시점의 선택 자체가 백테스트 성과를 규정하므로 원시 계약과 연속 시계열을 함께 저장합니다.

실습 11 · Parquet 푸시다운 & Polars vs Pandas

디스크 I/O 최적화 기술과 1,000만 행 대규모 데이터프레임 벤치마크입니다.

📦 [실습 11 · 20 & 22_pandas_polars_benchmark] 스토리지 실측

[조건자 푸시다운 (`20`)] Parquet Row Group 메타데이터의 Min/Max 통계를 활용해 불필요한 데이터를 디스크에서 아예 읽지 않고 건너뛰는 최적화 지원.

[Polars vs Pandas (`22`)] 1,000만 행 대규모 그룹 집계 및 멀티스레드 지연 연산(Lazy Execution)에서 Polars가 Pandas 대비 5~15배 빠른 속도와 절반 이하의 메모리 소비 기록.

Parquet의 조건자 푸시다운과 Polars의 지연 연산을 결합하여 대규모 데이터 분석 속도를 극대화합니다.

AIML Quant§2.4.2 임베디드 SQL

서버 없는 임베디드 분석 스택

복잡한 서버 설치 없이 파일 위에서 고성능 분석을 수행하는 현대적 퀀트 스택입니다.

DuckDB

Parquet 직접 쿼리, 벡터화 OLAP, 네이티브 ASOF JOIN 지원. 서버 없이 파일 위에서 강력한 SQL 실행.

Polars

Rust 기반 멀티스레드 지연 연산(Lazy Execution) 데이터프레임. 초고속 피처 엔지니어링.

SQLite

메타데이터, 설정, 소규모 관계형 테이블 관리의 신뢰할 수 있는 선택지.
