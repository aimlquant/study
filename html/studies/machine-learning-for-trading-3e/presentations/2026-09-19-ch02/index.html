2.1 Data Contracts

모델링 전 확정해야 할 4대 데이터 계약

1. 타임스탬프 의미론

Event Time (사건 발생) vs Knowledge Time (공시 접수) vs Ingestion Time (수집)의 엄격한 분리.

2. 기업행위 조정 방법론

분할/배당 요인의 소급 역방향(Backward) 적용 여부 및 총수익률(Total Return) vs 가격수익률 명시.

3. 식별자 안정성

티커 재사용 및 합병에 흔들리지 않는 영구 고유 식별자(FIGI, CIK, PermID) 매핑 체계 유지.

4. 수정 및 재작성 처리

거시지표나 재무제표 개정 시 의사결정 당시의 원본 수치(Vintage)를 복원할 수 있는 이중시간(Bitemporal) 지원.

2.2.1 Equities

주식: 기업행위 왜곡과 역방향 조정 알고리즘

미조정 가격의 파괴적 왜곡

  • 액면분할(7:1 등) 발생 시 원시 가격은 -86% 폭락으로 기록됨.
  • 미조정 가격을 모델 입력으로 사용 시 가짜 변동성과 매도 신호 생성.
역방향 조정 산식:
$$P_{\text{adj}, t} = P_t \times \prod_{t < t_s} \frac{1}{\text{split}} \times \prod_{t < t_d} \left(1 - \frac{D_t}{P_{t-1}}\right)$$

Apple 1980~2018 (4회 분할, 54회 배당):

5.9x 원시 가격 수익률
398.2x 조정 가격 수익률

$\rightarrow$ 무려 68배의 누적 성과 차이 발생!
자체 알고리즘과 Quandl 기준치 간 0.05% 오차 내 100% 일치 검증 완료.

2.2.2 ETPs

상장거래상품(ETP)의 이중 구조와 5대 위험

ETP의 2대 데이터 계층

  • 시장 거래층: 거래소에서 실시간 형성되는 시장 호가·체결.
  • 기초 보유층: 일말 기준 산출되는 순자산가치(NAV) 및 바스켓 비중.

5대 실패 모드 (Failure Modes)

  1. 수익률 정의: 분배금(배당) 재투자 반영 여부
  2. NAV 프리미엄/할인: 위기 시 시장가 $\neq$ NAV
  3. 유동성 불일치: 유동적 ETF 뒤 비유동 자산
  4. 룩스루 누수: 미래 보유비중을 과거에 적용
📦 [실습 03_etfs_eda] 100개 ETF(2006~2025) 패널에서 SPY와 원자재 ETF 간 23배 유동성 편차 및 독립 조정 과정에서 발생한 473건(0.1%)의 OHLC 불변식 위반(\(\text{Low} > \text{Open}\) 등) 확인.
2.2.3 Futures

선물: 만기 롤오버와 연속 시계열 구성

2대 연속 시계열 생성 방법

  • 비율 조정 (Ratio Adjustment): 과거 가격에 비율을 곱해 백분율 수익률(PnL Ratio)을 완벽 보존 (ML 표준 권장).
  • 차분 조정 (Difference Adjustment): 절대 스프레드를 가감해 달러 PnL 보존 (단, 과거 가격이 음수가 될 위험).

담보 이자 수익률 (Collateral)

선물 연속 시계열은 현물 지수와 달리 담보 이자가 제외된 초과 수익률(Excess Return) 대용치로 작동하므로 모델링 시 이를 명시해야 함.

📦 [실습 04~06_futures_continuous] 30개 CME 선물의 전자거래 23시간 세션 집계 및 거래량 역전일 기반 자동 롤 탐지 파이프라인 구축. 벤더 연속물과의 오차율 0% 검증.
2.2.4 Options

옵션: 체인에서 내재변동성 표면(IV Surface)으로

차원의 폭발과 꼬리 잡음

  • 수천 개 행사가 $\times$ 만기 조합 중 등가격(ATM) 근월물에만 유동성이 집중됨.
  • 원시 체인을 그대로 저장하지 않고 내재변동성 표면(IV Surface)으로 압축하여 피처화.

  • 롤오버 오염 제거 (09): 고정만기(30일물) 시계열에서 세타 감소와 롤오버 점프를 분리하여 순수 변동성 수익률 추출.
2.2.5 Crypto

디지털 자산: CEX 오더북과 DEX AMM 준비금

CEX (중앙화 거래소)

  • 전통 오더북(L2/L3) 구조.
  • 24/7 세션화 정의 필요 (00:00 UTC 기준 등).
  • 워시 트레이딩 필터링 및 거래소 무결성 검증.

DEX (탈중앙화 거래소)

  • 오더북 없음 $\rightarrow$ 상수곱(\(x \cdot y = k\)) 풀 준비금.
  • 호가 깊이 대신 슬리피지 함수 산출.
  • 비영구적 손실(IL) 및 MEV 모델링.
📦 [실습 10_crypto_perps_eda & 11] Binance 19개 코인 무기한 선물의 8시간 펀딩 비율(Funding Rate) 분석. 펀딩비 극단 신호가 미래 반전 수익률을 예측함을 입증하고 델타 뉴트럴 차익거래 성과 검증.
2.2.6 OTC Markets

장외시장(OTC): 외환, 채권, 스왑, 원자재

2.3 Data Sourcing

5대 데이터 품질 차원 프레임워크

1. 적시성 (Timeliness)

사건 발생부터 수집까지의 지연시간 측정.

2. 완전성 (Completeness)

자산·기간별 결측치(NaN) 탐지.

3. 정확성 (Accuracy)

거래소 원천 사실과의 일치성 대조.

4. 일관성 (Consistency)

스키마, 단위, 조정 정책의 시계열 안정성.

5. 유효성 (Validity)

OHLC 불변식(\(\text{High} \ge \text{Open}/\text{Close}\) 등) 준수.

이상치 격리 (Quarantine)

조용히 드롭하지 않고 감사 로그 생성.

2.3.2 Fatal Traps

실패 모드 ①: 시점 기준(PIT) 오류와 미래정보 누수

이중시간(Bitemporal) 축의 분리

  • Event Time: 분기 실적 발생일 (12월 31일)
  • Knowledge Time: SEC 공시 접수일 (2월 15일, 45일 지연)
  • 1월 백테스트에 12월 31일 실적을 투입하면 미래 정보를 미리 보고 거래하는 치명적 오류 발생.

📦 [실습 14_point_in_time_validation]

  • 중심 이동평균 누수: \(T-2 \sim T+2\) 중심 이평이 미래 가격을 훔쳐보는 현상 시각화.
  • FRED 빈티지 질의: vintage_date를 이용해 GDP 속보치(Advance)와 수정 확정치를 분리하는 이중시간 쿼리 구현.
2.3.2 Fatal Traps

실패 모드 ②: 생존자 편향 (Survivorship Bias)

사라진 패자의 손실을 지운 대가

오늘 생존한 종목으로만 과거 유니버스를 구성하면 상장폐지·파산 기업의 손실이 누락되어 수익률이 극단적으로 과대평가됨.

CRSP 상장폐지 종단 수익률 시나리오:
  • 파산/컴플라이언스 실패: -60%
  • M&A 피인수 프리미엄: +25%

📦 [실습 15_survivorship_bias] (1,000회 Draw)

미국 주식 3,199개 (상장폐지 777개) 대상 몬테카를로:

+41.7% 생존자 포트폴리오
+8.0%p 경험적 편향 과대평가

스트레스 위기 시나리오에서는 +15.3%p까지 왜곡 심화.

2.3.2 Fatal Traps

실패 모드 ③ & ④: 기업행위 및 식별자 무결성

③ 기업행위 조정 오류

  • 시점별 조정과 전구간 소급 조정을 섞을 때 발생하는 누수.

  • 과거 신호가 미래의 다른 기업 주가를 예측하는 가짜 상관관계 생성.

2.3.3 Due Diligence

벤더 실사(Due Diligence) 및 데이터 거버넌스

1. 데이터 품질 검증

  • 과거 수정치(Vintage) 지원 여부
  • 상장폐지 이력 포함 여부
  • 분할/배당 조정 산식 투명성

2. 법률 & 컴플라이언스

  • MNPI(미공개정보) 배제 확약
  • 웹 크롤링 ToS / 저작권 준수
  • 개인정보(GDPR/CCPA) 권리 확인

3. 기술 및 운영 SLA

  • API 레이트 리밋 & 가동시간
  • 대량 일괄 다운로드(Bulk) 지원
  • 스키마 변경 사전 통보 체계
내부 거버넌스 5대 기둥: (1) 계보 추적, (2) 덮어쓰기 없는 버전 관리, (3) 정제 로깅, (4) 검증 자동화(Great Expectations/Pandera), (5) 소스 교체 시 병렬 검증 운용.
2.4 Data Storage

접근 패턴이 저장 기술 선택을 결정합니다

파일 형식 (File Formats)

연구 반복 속도의 핵심. Parquet, Arrow IPC, HDF5, CSV.

핵심 기준: 압축률, 스캔 속도, 조건자 푸시다운(Predicate Pushdown).

데이터베이스 엔진 (Engines)

SQL 분석, 동시성, 시계열 조인이 필요할 때 추가.

핵심 기준: 인메모리/임베디드(DuckDB/Polars) vs 서버형(ClickHouse/Postgres).

파일 저장소 벤치마크 (표 2.4 실측)

파일 형식 파일 크기 (100만 행) 쓰기 시간 전체 스캔 시간 주요 특징 및 권장 용도

Parquet 40 MB (3.4배 압축) 0.07s (최저) 0.02s (최저) 컬럼형 압축, 푸시다운 지원, 퀀트 연구 표준 (압승)

2.4.2 Embedded SQL

서버 없는 임베디드 분석 스택

DuckDB

Parquet 직접 쿼리, 벡터화 OLAP, 네이티브 ASOF JOIN 지원. 서버 없이 파일 위에서 강력한 SQL 실행.

Polars

Rust 기반 멀티스레드 지연 연산(Lazy Execution) 데이터프레임. 초고속 피처 엔지니어링.

SQLite

메타데이터, 설정, 소규모 관계형 테이블 관리의 신뢰할 수 있는 선택지.

표준 퀀트 연구 파이프라인: [파티셔닝 Parquet 레이크] \(\rightarrow\) [DuckDB 고속 SQL] \(\rightarrow\) [Polars 피처 생성]

2.5 Conclusion

재현 가능한 퀀트 연구를 위한 4대 데이터 원칙

1. 가정의 명시화

타임스탬프, 캘린더, 기업행위 규칙을 암묵적으로 넘기지 말고 데이터 계약 메타데이터로 고정하라.

2. 가짜 알파 원천 봉쇄

시점 기준(PIT) 이중시간 쿼리와 생존자 편향 없는 유니버스를 연구 첫날부터 구축하라.

3. 시장 구조 부합 모델링

주식 분할, 선물 롤오버, 옵션 표면, 크립토 AMM 슬리피지를 자산군 특성에 맞게 다루어라.

4. 단순하고 빠른 스토리지

Parquet + Polars/DuckDB로 시작하고, 운영 비용이 정당화될 때 서버 DB를 도입하라.
