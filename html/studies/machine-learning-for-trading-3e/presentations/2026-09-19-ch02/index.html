데이터는 전략의 원재료이자 첫 번째 위험 요소입니다

머신러닝 알고리즘 이전에 데이터 파이프라인의 조용한 결함을 먼저 잡아야 합니다.

1. 분류와 내재 규칙

데이터는 단순한 숫자가 아닙니다. 타임스탬프, 캘린더, 기업행위, 수정 규칙이 결합된 계약입니다.

2. 자산군별 시장 구조

주식의 NBBO, 선물의 롤오버, 옵션의 표면, 크립토의 AMM 슬리피지까지 시장마다 가격 정의가 다릅니다.

3. 가짜 알파의 원천 봉쇄

시점 기준(PIT) 오류, 생존자 편향, 기업행위 왜곡을 소싱 및 저장 단계에서 사전에 차단합니다.

머신러닝 트레이딩 실패의 대부분은 알고리즘이 아닌 데이터 파이프라인의 조용한 결함에서 발생합니다.

AIML Quant§2.1 데이터 계약

모델링 전 확정해야 할 4대 데이터 계약

하위 파이프라인 코드가 제각기 해석하지 못하도록 전사적으로 고정해야 하는 원칙입니다.

1. 타임스탬프 의미론

Event Time(사건 발생) vs Knowledge Time(공시 접수) vs Ingestion Time(수집)을 엄격히 분리.

2. 기업행위 조정 방법

분할/배당 요인의 소급 역방향(Backward) 적용 방식 및 총수익률(Total Return) vs 가격수익률 명시.

3. 식별자 안정성

티커 재사용 및 M&A에 흔들리지 않는 영구 고유 식별자(FIGI, CIK, PermID) 매핑 체계 유지.

4. 수정 및 재작성 처리

거시지표나 재무제표 개정 시 의사결정 당시의 원본 수치(Vintage)를 복원할 수 있는 이중시간 지원.

이 4대 계약이 누락되면 이후 단계의 특징 추출과 백테스트 전체가 조용히 왜곡됩니다.

AIML Quant§2.2.2 ETP

상장거래상품(ETP)의 이중 구조와 5대 위험

ETP는 거래소 상장 래퍼층과 하위 포트폴리오 보유층이라는 이중 구조를 지닙니다.

ETP의 2대 데이터 계층

시장 거래층: 거래소에서 실시간 형성되는 호가·체결.

기초 보유층: 일말 기준 산출되는 순자산가치(NAV) 및 바스켓 비중.

5대 실패 모드

1. 분배금 재투자 여부 / 2. 위기 시 시장가 \(\neq\) NAV 괴리

3. 유동성 불일치 / 4. 룩스루 누수 (미래 비중 사용)

📦 [실습 3 · 03_etfs_eda] 100개 ETF 패널에서 SPY와 원자재 ETF 간 23배 유동성 편차 확인. 벤더의 가격 4개 필드 독립 조정으로 인한 473건(0.1%)의 OHLC 불변식 위반(\(\text{Low} > \text{Open}\) 등) 진단.

ETP 분석 시 시장 가격과 NAV 수익률을 명확히 구분하고 보유 비중의 PIT를 통제해야 합니다.

AIML Quant§2.2.3 선물

선물: 만기 롤오버와 연속 시계열 구성

영구 티커가 없는 선물 계약들을 경제적 손익을 보존하는 단일 시계열로 결합하는 기법입니다.

2대 연속화 방법론

비율 조정 (Ratio): 과거 가격에 비율을 곱해 백분율 수익률(PnL Ratio)을 완벽 보존 (ML 표준 권장).

차분 조정 (Difference): 절대 스프레드를 가감해 달러 PnL 보존 (단, 과거 가격 음수 위험).

담보 이자 수익률 (Collateral)

선물 연속 시계열은 현물 지수와 달리 담보 이자가 제외된 초과 수익률(Excess Return) 대용치로 작동하므로 모델링 시 명시해야 합니다.

AIML Quant§2.2.5 크립토

디지털 자산: CEX 오더북과 DEX AMM 준비금

전통 호가창을 가진 CEX와 풀 준비금 비율로 가격을 결정하는 DEX가 공존합니다.

CEX (중앙화 거래소)

전통 오더북(L2/L3) 구조이나 24/7 세션화 기준(00:00 UTC)이 필요하며 워시 트레이딩 필터링이 필수적입니다.

DEX (탈중앙화 거래소)

오더북 부재 $\rightarrow$ 상수곱(\(x \cdot y = k\)) 풀 준비금. 호가 깊이 대신 슬리피지 함수, 비영구적 손실(IL), MEV 모델링.

DEX에서는 오더북 재구성이 성립하지 않으며 준비금 기반으로 유동성과 슬리피지를 계산해야 합니다.

AIML Quant§2.3 데이터 품질

5대 데이터 품질 차원 프레임워크

데이터 품질 결함은 백테스트에서는 가짜 알파를 만들고 실거래에서는 큰 손실을 초래합니다.

1. 적시성 (Timeliness)

사건 발생부터 수집까지의 지연시간 측정.

2. 완전성 (Completeness)

자산·기간별 결측치(NaN) 공백 탐지.

3. 정확성 (Accuracy)

거래소 원천 사실과의 일치성 대조.

4. 일관성 (Consistency)

스키마, 단위, 조정 정책의 시계열 안정성.

5. 유효성 (Validity)

OHLC 불변식(\(\text{High} \ge \text{Open}/\text{Close}\) 등) 준수.

이상치 격리 (Quarantine)

조용히 드롭하지 않고 감사 로그 생성.

AIML Quant§2.4.2 임베디드 SQL

서버 없는 임베디드 분석 스택

복잡한 서버 설치 없이 파일 위에서 고성능 분석을 수행하는 현대적 퀀트 스택입니다.

DuckDB

Parquet 직접 쿼리, 벡터화 OLAP, 네이티브 ASOF JOIN 지원. 서버 없이 파일 위에서 강력한 SQL 실행.

Polars

Rust 기반 멀티스레드 지연 연산(Lazy Execution) 데이터프레임. 초고속 피처 엔지니어링.

SQLite

메타데이터, 설정, 소규모 관계형 테이블 관리의 신뢰할 수 있는 선택지.

표준 연구 파이프라인: [파티셔닝 Parquet 레이크] $\rightarrow$ [DuckDB 고속 SQL] $\rightarrow$ [Polars 피처 생성].

AIML Quant§2.5 요약

타임스탬프, 캘린더, 기업행위 규칙을 암묵적으로 넘기지 말고 데이터 계약 메타데이터로 고정하라.
