무엇을 GNN에 먹이는가

CSV를 노드 번호가 매겨진 텐서로 바꾸고, 정답이 새지 않게 학습·검증·테스트로 나눈다.

어디서 두 과제가 갈라지는가

무엇으로 좋고 나쁨을 읽는가

정답이 치우친 데이터에서는 정확도 하나가 아니라 정밀도·재현율과 혼동 행렬이 필요하다.

구성 요소는 같고 끼우는 부품이 다르다는 점이 이 장의 논점이다.

AIML Quant11장 연결

인코더가 representation을 만들고 디코더가 예측으로 바꾼다

GNN 한 layer는 이웃을 모으고(AGGREGATE) 자기 representation을 갱신(UPDATE)한다. 11장 §11.2, §11.5의 정리다.

인코더와 디코더

인코더는 구조와 노드 특징을 받아 노드마다 벡터를 만들고, 디코더는 그 벡터에서 라벨이나 연결 여부를 복원한다. 복원 오차가 학습 신호다.

message passing 한 layer

이웃 representation의 합(또는 평균)을 만들고, 자기 이전 representation과 함께 가중치·비선형 함수를 거쳐 새 representation을 만든다.

layer를 쌓으면

두 layer이면 두 걸음 안의 이웃 정보가 담긴다. 12장의 모든 인코더가 convolution layer 두 개인 이유다.

12장의 두 과제는 '무엇을 복원하는 디코더인가'만 다르다.

상세 설명 ↗ /
AIML Quant11장 연결

이웃의 합과 평균은 같은 노드에 다른 값을 준다

노드 u의 이전 representation이 [1, 0], 이웃이 [0, 2], [2, 0], [1, 1]인 작은 예(이해를 위한 예)다.

왼쪽 이웃 세 개를 AGGREGATE가 하나로 모은다. 합이면 [3, 3]이라 새 representation이 [4, 3]이고, 평균이면 [1, 1]이라 [2, 1]이다(가중치는 단위 행렬, 활성화는 ReLU로 가정). 이웃이 많을수록 합은 커지고 평균은 이웃 수와 무관한 크기를 유지한다.

정규화는 이웃 수가 다른 노드를 같은 척도에서 비교하려는 장치다.

상세 설명 ↗ /
AIML Quant11장 연결

GCN은 차수로 누르고 GAT는 이웃마다 가중치를 배운다

세 인코더의 차이는 '이웃을 어떻게 집계하는가'에 있다(11장 §11.6.1–11.6.3).

GCN — 대칭 정규화

이웃 v의 기여를 두 노드의 이웃 수 곱의 제곱근으로 나눈다. 수천 번 인용된 논문이 message passing을 지배하지 않게 하는 효과가 있고, 차수 정보는 흐려진다.

GAT — attention

이웃마다 학습되는 가중치를 softmax로 합이 1이 되게 만들어 가중합을 구한다. 여러 head로 서로 다른 관계를 병렬로 본다.

12장에서 보이는 흔적

GAT 매개변수가 22,025개로 GCN의 약 8배인 것은 attention 계수와 8개 head 때문이다. 이질 그래프의 GCN은 GraphConv로 바뀐다.

매개변수가 많다고 성능이 좋은 것은 아니며, 이 장 결과가 그것을 보여 준다.

AIML Quant11장 연결

사용자 임베딩은 shallow 임베딩이고 그 한계가 남는다

노드마다 벡터 한 줄을 갖는 lookup 테이블은 11장 §11.3에서 한계가 정리된 방식이다.

11장이 든 네 가지 한계

매개변수가 노드 수에 비례하고, 노드 사이에 공유되지 않으며, 노드 특징을 쓰지 못하고, 학습 때 없던 노드는 임베딩이 없다.

12.2에서의 모습

사용자 610명마다 학습되는 행을 두는 Embedding이 바로 lookup 테이블이다. 그 위에 이질 GNN이 이웃 정보를 얹는다. 신규 사용자 처리는 12장이 다루지 않는다(구조에서 읽은 해석).

12.1과 12.2의 설정 차이

Elliptic은 라벨 없는 노드까지 그래프에 있는 준지도 설정이다. 평가 대상이 학습 때 그래프 안에 있었는지가 두 실습의 가정을 가른다.

'새 사용자·새 거래가 오면 어떻게 하는가'는 12장 밖의 질문으로 남는다.

PyG는 엣지를 [2, 엣지 수] 모양으로 기대하므로, 엣지 하나가 한 줄인 표를 가로세로로 뒤집는다.

    dtype=torch.long

# 출력 예: tensor([[0, 2, 4, ...],     ← 출발 노드 목록
#                  [1, 3, 5, ...]])    ← 도착 노드 목록
# 세로 한 쌍 (0, 1)은 "노드 0에서 노드 1로 가는 엣지 하나"

작은 예(이해를 위한 예): 노드 A, B, C가 0, 1, 2이고 엣지가 A→B, B→C이면 [[0, 1], [1, 2]]다. 세로로 읽으면 엣지 하나(0→1, 1→2), 가로로 읽으면 출발 목록 [0, 1]과 도착 목록 [1, 2]다.

전치(.T)가 이 단계의 핵심이다.

엣지 하나가 텐서의 열 하나가 된다

노드 A, B, C에 번호 0, 1, 2를 주고 A→B, B→C 두 엣지가 있는 가상의 3노드 그래프다.

왼쪽 그래프를 오른쪽 텐서로 옮기면 윗행이 출발 노드 번호(0, 1), 아랫행이 도착 노드 번호(1, 2)다. 같은 색이 같은 엣지이므로 첫 열 (0, 1)은 'A에서 B로', 둘째 열 (1, 2)는 'B에서 C로'를 뜻한다. Elliptic의 실제 데이터가 아니라 개념용 예다.

Elliptic은 같은 모양의 텐서가 [2, 234355]로 커졌을 뿐이다.

convolution layer 종류를 인자로 받는 두 layer 골격이 세 인코더의 공통부다

첫 layer는 입력에서 은닉으로, 둘째 layer는 은닉에서 출력으로 가며 사이에 ReLU를 둔다.

class BaseGraphModel(torch.nn.Module):
    def __init__(self, input_dim, hidden_dim, out_dim, conv_layer, **conv_kwargs):
        super().__init__()
        self.conv1 = conv_layer(input_dim, hidden_dim, **conv_kwargs)
        self.conv2 = conv_layer(hidden_dim, out_dim, **conv_kwargs)
    def forward(self, x, edge_index):
        x = F.relu(self.conv1(x, edge_index))
        return self.conv2(x, edge_index)

class SAGE(BaseGraphModel):   # SAGEConv는 추가 인자가 필요 없다
    def __init__(self, input_dim, hidden_dim, out_dim):
        super().__init__(input_dim, hidden_dim, out_dim, conv_layer=SAGEConv)

원문의 super(BaseGraphModel, self) 표기를 줄여 쓴 발췌다. 합성곱이 두 layer이므로 각 노드 representation은 2-hop 이웃까지의 정보를 담는다.

모델을 바꾸는 일이 클래스 한 줄을 바꾸는 일이 된다.

AIML Quant교재 §12.1.4

log_softmax는 클래스 점수를 로그 확률로 바꾸고 틀릴수록 큰 벌점을 준다

불법과 합법 두 클래스의 점수가 (2.0, 0.0)인 작은 예(이해를 위한 예)다.

\[\text{softmax}(2,0)\approx(0.881,\ 0.119),\qquad \log\approx(-0.127,\ -2.127)\]

읽는 법

첫 값이 불법, 둘째 값이 합법의 로그 확률이다. 로그를 취하면 아주 작거나 큰 수에서도 계산이 안정적이다.

벌점

정답이 합법이면 벌점 2.127, 불법이면 0.127이다. 불법에 높은 확률을 주고 틀린 쪽이 더 크게 수정된다.

loss 짝

log_softmax 출력에는 음의 로그 우도가 맞는 짝이다. 로그 확률에 한 번 더 적용해도 값이 같아 학습 신호는 변하지 않는다(수식 도출).

loss는 '얼마나 틀렸는지'의 벌점이고 학습은 그것을 줄이는 방향이다.

실선은 message passing에 쓰이는 엣지, 점선은 정답으로만 쓰이는 엣지다. 왼쪽은 u의 임베딩이 이미 m의 정보를 받은 채 u–m을 맞히지만, 오른쪽은 m의 정보 없이 맞혀야 한다. 개념용 도해이며 실제 MovieLens 값이 아니다.

그래서 학습 엣지를 메시지용과 감독용으로 겹치지 않게 나눈다.

인코더–디코더 아키텍처 — 임베딩을 만들고 내적으로 궁합을 잰다

인코더는 임베딩 생성과 이질 GNN 두 단계이고, 디코더는 사용자·영화 벡터의 dot product이다.

왼쪽 세 상자가 임베딩 생성이다. 사용자는 노드 ID 임베딩 한 경로뿐이고 영화는 장르 경로와 ID 경로의 합이다. 이질 GNN이 이웃 정보를 얹은 뒤 감독 엣지의 (사용자, 영화) 쌍마다 dot product를 계산한다.

디코더가 노드 하나가 아니라 노드 쌍에 점수를 낸다는 점이 12.1과의 차이다.

사용자는 행렬만 학습하고 영화는 장르 변환과 ID 임베딩을 더한다

사용자에게는 초기 특징이 없어 임베딩 행렬이 학습으로 채워진다.

class MovieLensEmbedding(torch.nn.Module):
    def __init__(self, user_input_dim, movie_input_dim, out_dim):
        super().__init__()
        self.movie_lin = torch.nn.Linear(20, out_dim)       # 20차원 장르 → out_dim
        self.user_emb = torch.nn.Embedding(user_input_dim, out_dim)
        self.movie_emb = torch.nn.Embedding(movie_input_dim, out_dim)
    def forward(self, data):
        return {"user": self.user_emb(data["user"].node_id),
                "movie": self.movie_lin(data["movie"].x)
                         + self.movie_emb(data["movie"].node_id)}

영화는 '이미 아는 장르 정보'와 '학습으로 배우는 정보'를 함께 갖는다. 사용자 행은 11장의 shallow 임베딩과 같은 lookup 테이블이다.

장르를 아는 영화와 이력만 아는 사용자는 출발 정보가 다르다.

to_hetero()가 메타데이터에 맞춰 동질 모델을 이질 모델로 자동 변환한다.

class HeteroBaseModel(torch.nn.Module):
    def __init__(self, metadata, input_dim, hidden_dim, out_dim, base_model):
        super().__init__()
        self.base_model = base_model(input_dim, hidden_dim, out_dim)
        self.hetero_model = to_hetero(self.base_model, metadata=metadata)
    def forward(self, x_dict, edge_index_dict):
        return self.hetero_model(x_dict, edge_index_dict)

class HeteroSAGE(HeteroBaseModel):
    def __init__(self, metadata, input_dim, hidden_dim, out_dim):
        super().__init__(metadata, input_dim, hidden_dim, out_dim, SAGE)

메타데이터는 노드·엣지 유형의 집합이고 합성곱은 거기에 명시된 유형을 따라 진행된다. 이 장에는 엣지 유형이 하나뿐이지만 더 복잡한 시나리오에서는 유형마다 다른 합성곱을 쓸 수 있다.

동질 실습에서 만든 부품이 이질 실습에서 재사용된다.

AIML Quant교재 §12.2.4

dot product가 클수록 궁합이 좋고 sigmoid가 그것을 확률로 바꾼다

사용자 벡터 [1, 2]와 영화 벡터 [2, 1]의 작은 예(이해를 위한 예)다.

\[z_u\cdot z_m=1\cdot2+2\cdot1=4,\qquad \sigma(4)=\frac{1}{1+e^{-4}}\approx0.982\]

기호

$z_u$는 사용자 벡터, $z_m$은 영화 벡터, $\sigma$는 점수를 0과 1 사이 확률로 바꾸는 sigmoid다.

벌점

실제 링크면 벌점 약 0.018로 작고, 링크가 없는 쌍이면 약 4.02로 크다. 점수 0이면 확률 0.5, 벌점은 어느 쪽이든 약 0.693이다.

softmax와의 대응

노드 분류가 여러 클래스 중 하나를 고르는 문제라면, 여기서는 '링크 있다/없다'의 이진 문제다.

같은 '벌점 최소화'가 클래스 선택에서 링크 판정으로 바뀐다.

사용자 벡터와 방향이 비슷한 영화일수록 dot product가 크다

사용자 [1, 2]와 영화 세 편의 2차원 가상 벡터를 비교한다.

영화 A [2, 1]은 사용자와 방향이 비슷해 dot product 4(확률 약 0.98), 영화 B [-1, 1]은 dot product 1(약 0.73), 반대쪽을 향한 영화 C [-2, -1]는 dot product -4(약 0.02)다. 학습된 임베딩이 아니라 계산을 보이려는 가상의 값이다.

추천은 이 점수가 큰 영화를 우선 보여 주는 일이다.
