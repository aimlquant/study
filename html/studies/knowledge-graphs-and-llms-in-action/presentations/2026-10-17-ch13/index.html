문제

단순 벡터 검색만으로는 질문 속 인물과 관계를 파악해 정확한 맥락을 찾기 어렵고, AI 에이전트도 어떤 검색 도구를 써야 할지 제대로 판단하지 못한다.

메커니즘 (작동 원리)

원본 문서와 지식 그래프(KG)를 하나로 연결한 뒤, ReAct 에이전트가 질문에 맞춰 '관계를 단서로 문서를 찾는 도구'와 '쿼리(Cypher)로 그래프를 직접 조회하는 도구' 중 알맞은 것을 골라 사용한다.

판단 (도구 선택 기준)

질문에 두 대상이 명확히 주어지면 '문서 선택기'를, 지식 그래프만으로 답할 수 있으면 'KG 리더'를 쓴다. 만약 두 도구로 답을 찾지 못하면 '벡터 검색'을 보조 수단으로 활용하고, 최종 근거는 사람이 직접 검증한다.

같은 문서 위에 KG를 얹으면 관계를 먼저 특정하고 그 관계를 언급한 문서를 골라 줄 수 있다.

사전 학습된 LLM + 지금까지 오간 질문과 답을 기억하는 메모리

class Agent:
    def __init__(self, model: str = "gpt-4o-mini", system: str = None):
        self.model = model
        self.messages = list()
        self.client = OpenAI(api_key=os.environ['OPENAI_API_KEY'])
        self.messages.append({"role": "system", "content": self.system})

    def __call__(self, message: str) -> str:
        self.messages.append({"role": "user", "content": message})
        answer = self.execute()
        self.messages.append({"role": "assistant", "content": answer})
        return answer

self.messages가 메모리다. 호출마다 전체 이력을 다시 보내므로 "기억"은 클라이언트가 만든다.

AIML Quant교재 §13.4.1

RAG는 환각·최신성·투명성·데이터 프라이버시 문제를 다루려고 개발된 기법

사전 학습된 LLM의 지식과 언어 이해 능력에, 질문과 관련해 외부 데이터 소스에서 검색해 온 추가 맥락을 결합해 답을 생성한다.

하는 일

질문과 외부에서 검색한 맥락을 함께 받아 답을 생성한다.

효과

답 생성의 범위를 제공된 맥락으로 제한하므로 사실을 지어낼 가능성이 크게 줄어든다.

NOTE

모델은 확률적이어서 RAG를 써도 엉뚱한 방향으로 갈 수 있다. 시스템은 사람을 대체하는 것이 아니라 보강해야 하며, 사람을 루프 안에 두는 것(human in the loop)이 필수다.

근거화는 환각을 없애는 것이 아니라 줄이는 것이고, 마지막 확인은 사람의 몫이다.

GraphRAG의 그래프는 두 가지 특징을 동시에 가집니다. 하나는 노드와 화살표 자체에 텍스트 정보를 담는 것(텍스트 속성 그래프)이고, 다른 하나는 그 정보의 출처가 된 원본 문서를 줄로 묶어두는 것(텍스트 연결 그래프)

위 그림을 보면 맨 위 '원본 문서(일기 한 쪽)'에서 중간의 '등장 키워드(Entity)'를 뽑아내고, 이를 맨 아래 '지식 그래프의 인물(Person) 관계도'와 연결했다.

맨 아래 지식 그래프만 보면 "누가 누구에 대해 말했다"는 사실은 알 수 있지만, "그게 일기장 몇 페이지에 적혀 있는지"는 알 수 없습니다. 문서와 그래프를 이어 두어야만, 인물 관계를 단서로 삼아 원본 일기장(근거 문장)을 정확히 역추적해 찾아낼 수 있습니다.

질문의 유형에 따라 3가지 검색 도구 중 사용할 도구가 결정된다

관계도를 바로 읽는 'KG 리더', 관계를 단서로 원본 문서를 찾는 '문서 선택기', 그리고 앞의 두 도구가 실패했을 때 쓰는 비상용 '벡터 검색기'.

관계나 집계만 필요하면 KG 리더, 두 대상 사이의 상호작용 내용이 필요하면 문서 선택기, 앞의 둘이 맥락을 못 주면 벡터 검색으로 간다. 세 도구의 호출 조건은 13.4.4의 도구 설명문에서 읽어 다시 그린 재구성이다.

질문의 성격이 도구를 가르고, 도구를 고르는 기준은 도구 설명문이다.

생각하고 행동하고 관찰하는 루프로 도구들을 에이전트 하나에 통합한다

명확한 실행 순서가 없는 여러 도구가 있으므로 ReAct(Reason and Act) 에이전트를 쓴다.

Thought

무엇을 할지 추론한다.

Action

도구를 호출하는 행동을 한다.

Observation

그 결과를 관찰하고 접근을 다듬는다. 원래 질문에 답하기에 충분한 맥락을 얻었다고 판단하면 루프를 끝낸다.

얻은 정보가 만족스럽지 않으면 에이전트는 다른 도구를 쓴다.

llm = ChatOpenAI(model=MODEL, temperature=0)
prompt = load_custom_prompt("../prompts/prompt_structured.txt")   # 교재 본문은 hub.pull(...)
agent = create_structured_chat_agent(llm, tools, prompt)

요약 — 이 장의 핵심 정리

에이전트 → RAG → 벡터 RAG의 한계 → 그래프 RAG → KG 통합 설계. 이 순서가 13장의 논리다.

AI 에이전트

모든 AI 에이전트의 핵심에는, 에이전트의 두뇌 역할을 하는 LLM 모델, 그 모델을 안내하는 프롬프트, 그리고 에이전트가 바깥세상과 상호작용할 수 있게 해 주는 도구 집합의 조합이 자리합니다.

RAG

검색 증강 생성(RAG)은 생성 모델과 정보 검색을 결합하여, AI 에이전트 같은 지능형 시스템을 만드는 프레임워크입니다. 그렇게 함으로써 환각·최신성·투명성·데이터 프라이버시 같은 LLM 고유의 문제들을 다룹니다.

벡터 RAG의 한계

벡터 기반 RAG 시스템은 여러 단점을 겪습니다. 제한된 추론 능력, 확장성 문제, 그리고 잡음과 관련 정보 누락을 포함한 검색의 부정확성이 그것입니다.

그래프 RAG

그래프 RAG는 KG를 LLM과 통합하여, KG 안의 구조화된 관계적 다중 홉 패턴을 활용함으로써 추론 능력과 정보 검색의 정밀도를 강화합니다. 또한 KG는 질의응답 과정에 더 많은 통제와 투명성을 제공합니다.

KG 통합 방법

KG를 RAG 시스템에 통합하는 방법은 그래프 설계에 따라 결정됩니다. 가장 유용한 KG는 텍스트 속성 그래프와 텍스트 짝지음 그래프를 결합한 것으로, 이를 통해 잘 정제된 구조화 지식과, 문서 및 그 메타데이터를 함께 활용할 수 있습니다.
