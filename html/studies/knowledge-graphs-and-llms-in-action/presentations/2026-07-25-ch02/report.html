    0. 핵심 질문

    One Sentence지식 표현·추론·사람의 결정을 어떻게 하나의 지능형 자문 시스템으로 묶는가?

    지능형 시스템의 품질은 모델 하나의 유창함보다 어떤 지식을 기억하고, 어떤 방식으로 추론하며, 누가 결과를 검토하고 행동을 확정하는지에 달려 있습니다. 관계와 출처를 명시하는 KG와 언어 패턴을 다루는 LLM은 서로 다른 책임을 맡습니다.

    핵심은 기술을 많이 결합하는 것이 아니라 지식 표현, 언어 처리, 추론, 사람의 결정이 서로 다른 상태와 책임을 갖도록 만드는 데 있습니다. 결과가 사실인지 예측인지 권고인지 구분하고, 근거와 갱신 경로를 함께 남겨야 합니다.

    표 1이 장을 읽는 네 가지 질문
    질문확인할 것
    무엇을 기억하는가?명시적 사실·관계와 암묵적 패턴
    어떻게 결론을 내는가?규칙·일반화·확률적 후보의 차이
    누가 행동을 확정하는가?시스템 권고와 사람 결정의 경계

    §2.1 · Source Section

    2.1 지능이란 무엇인가? — 지식과 추론이라는 두 축

    지능은 지식을 습득하고 적용하는 능력이다.지식 표현과 추론은 서로의 능력과 한계를 결정한다.

    지식 표현은 도메인 정보를 구조화·부호화·전달하는 언어이고, 추론은 그 정보와 규칙·증거를 이용해 결론이나 예측을 만드는 과정입니다. 표현이 풍부할수록 처리 비용이 커질 수 있어 도메인과 과제에 맞는 균형이 필요합니다.

    한 지능형 시스템에는 지식 베이스와 추론 엔진이 여러 개 있을 수 있습니다. 이들은 순차 또는 병렬로 상호작용하고, 한 엔진의 출력이 다른 엔진이나 지식 베이스의 입력이 되며 지식을 정교화합니다.

    §2.2 · Source Section

    2.2 지능형 시스템 설계하기 — 의료 진단 시나리오로 구조 잡기

    의료 진단 시나리오로 구성요소와 책임을 구체화한다.전역 지식과 환자 맥락을 결합하되 최종 권한을 구분한다.

    의료 진단 지원은 지식·추론·사용자 상호작용을 함께 보여 주는 복잡한 사례입니다. 시스템은 질문·검사·치료 선택지를 제안하기 위해 일반 의학 지식과 환자의 구체적 맥락을 결합해야 합니다.

    여러 알고리즘과 도구의 출력을 연결할 때는 단순한 모델 성능보다 어떤 결과가 사실, 예측, 권고인지 표시하는 상태 계약이 중요합니다. 이 장은 KG와 LLM을 그 계약 안에서 배치합니다.

    §2.2.1 · Source Section

    2.2.1 지능형 시스템이란 무엇인가? — 사용자를 돕고 스스로 진화하는 시스템

    지능형 시스템은 사용자를 AI·ML과 연결해 의미 있는 목표를 달성하게 한다.상호작용과 피드백으로 지식을 진화시킨다.

    Geoff Hulten의 정의는 지능형 시스템이 사용자를 대체하는 장치가 아니라 사용자가 복잡한 과제를 완수하도록 돕는 시스템임을 강조합니다. 시스템은 데이터 원천과 환경을 관찰해 지식을 습득하고, 내부 과정을 거쳐 사용자에게 결과를 제공합니다.

    사용자 피드백은 중요하지만 자동으로 정답이 되지는 않습니다. 클릭·수용·실행 결과를 관찰로 기록하고 검증한 뒤 지식 베이스에 반영해야 잘못된 피드백이 새 사실로 굳는 일을 막을 수 있습니다.

    §2.2.2 · Source Section

    2.2.2 지능형 시스템의 분류 — 자율 시스템과 자문 시스템

    자율 시스템은 행동을 직접 확정한다.자문 시스템은 권고를 제공하고 사용자가 결정한다.

    자율 시스템은 최소한의 사람 입력으로 실시간 결정을 내리고 환경 변화에 적응하며 직접 실행합니다. 자문 시스템은 맥락에 맞는 정보와 선택지를 제공하지만 조치를 확정하지 않습니다.

    화면에 승인 버튼이 있다는 이유만으로 자문 시스템이 되지는 않습니다. 사용자가 근거와 불확실성을 보고 거절·보류할 수 있고, 이의 제기·감사·롤백 경로가 실제 운영 과정에 있어야 최종 결정권이 보존됩니다.

    §2.2.3 · Source Section

    2.2.3 지능형 시스템의 특성 — 설계를 이끄는 네 가지 축

    목표·경험·지식 생성·오케스트레이션이 네 설계 축이다.지식 습득과 추론은 이 축을 구현하는 핵심 과정이다.

    의미 있는 목표는 무엇을 최적화할지 정하고, 지능적 경험은 맞는 제안의 가치를 키우면서 틀린 제안의 비용을 줄이는 인터페이스를 요구합니다. 지식 생성과 갱신은 변화하는 도메인과 피드백을 다루며, 오케스트레이션은 여러 알고리즘의 순서·위험·품질을 관리합니다.

    이 책은 정립된 도메인 지식 베이스를 사용하고, 사용자를 대신해 행동하기보다 조치를 제안하며, 결과 피드백으로 지식을 확장하는 IAS에 초점을 맞춥니다.

    §2.3 · Source Section

    2.3 지식 습득과 표현 — KG와 LLM이 갈라지는 지점

    KG는 명시적이고 부분 수정 가능한 지식을 만든다.LLM은 유연하지만 불투명한 통계 패턴을 학습한다.

    KG의 지식 습득은 데이터의 개체·관계·속성을 온톨로지나 스키마에 맞춰 그래프로 바꾸는 과정입니다. 도메인 전문가는 원천과 의미를 고르고 결과를 평가합니다. 준비 비용은 크지만 노드와 관계를 직접 조회·수정할 수 있습니다.

    LLM은 대규모 텍스트를 자기지도 방식으로 학습해 매개변수 공간에 암묵적 패턴을 저장합니다. 맥락과 언어 관계를 유연하게 다루지만 특정 사실의 위치를 확인하거나 부분 갱신하기 어렵고, 보통 재학습이나 미세 조정이 필요합니다.

    보완 관계

    LLM의 언어 접근성과 KG의 명시적 통제 가능성을 결합하되, 두 표현을 같은 종류의 지식 저장소로 취급하지 않습니다.

    §2.4 · Source Section

    2.4 추론 — 불확실성·추론·일반화라는 세 가지 열린 질문

    추론 엔진은 불확실성·도출·일반화를 다룬다.연역과 귀납, LLM의 확률적 출력은 확실성 수준이 다르다.

    연역은 일반 전제와 규칙에서 구체적 결론을 만들며 전제가 참이면 결론을 보장합니다. 귀납은 관찰에서 폭넓은 패턴을 만들기 때문에 처음 보는 사례에 일반화할 수 있지만 결론이 틀릴 수 있습니다.

    책의 Claude 3.5 Sonnet 사례는 단순화한 농부와 양 문제에서 당시 모델이 익숙한 문제 절차를 끌어와 불필요한 왕복을 만든 역사적 스냅숏입니다. 이는 특정 버전·과제 조건의 관찰이며 현재 모든 LLM의 영구 능력 판정이 아닙니다.

    KG와 LLM 어느 쪽도 인간의 상식적 추론을 본질적으로 보장하지 않습니다. 따라서 규칙 결론·통계 예측·생성 후보를 서로 다른 상태로 표시하고, 중요한 결정에서는 사람이 근거를 검토해야 합니다.

    리스팅 2.1 추론 능력을 확인하기 위한 프롬프트

    A farmer stands at the side of the river with a sheep. There is a boat with
enough room for one person and one animal. How can the farmer get himself and
the sheep to the other side of the river using the boat in the smallest
number of trips?

    조건만 읽으면 농부와 양이 함께 한 번 건너면 끝납니다. 이 짧은 입력은 모델이 실제 조건보다 익숙한 문제 틀을 우선하는지 확인합니다.

    §2.5 · Source Section

    2.5 추론 엔진 — 지식 베이스와 피드백 루프

    여러 추론 엔진이 지식 베이스를 읽고 쓸 수 있다.조치·환경 관찰·새 지식이 피드백 루프를 만든다.

    추론 엔진은 연역·귀납 같은 한 전략만 사용하거나 여러 전략을 조합할 수 있습니다. 엔진의 제안이나 행동은 환경을 바꾸고, 새 관찰은 다시 처리되어 지식 베이스를 확장하며 다음 제안을 이끕니다.

    이 순환에서 관찰은 아직 검증된 사실이 아닙니다. 후보, 사람의 결정, 환경 결과, 검증된 지식의 상태를 분리해야 오류가 피드백을 타고 증폭되는 것을 막을 수 있습니다.

    §2.5.1 · Source Section

    2.5.1 순수 연역적 추론 엔진의 한계 — 완벽한 지식 베이스라는 비현실적 전제

    연역은 완전하고 정확한 전제 안에서 강하다.현실의 지식 베이스는 흔히 불완전하다.

    의료 진단에서 질병·증상·검사 비용·환자 선호가 모두 정확히 부호화돼 있다면 연역적 추론기는 최적 조치의 순서를 논리적으로 계산할 수 있습니다. 설명 경로도 전제와 규칙으로 추적할 수 있습니다.

    하지만 필요한 모든 정보와 규칙을 최신·정확하게 유지한 완벽한 지식 베이스는 현실에서 구하기 어렵습니다. 누락되거나 틀린 전제는 논리적으로 깔끔하지만 현실과 어긋난 결론을 만들 수 있습니다.

    §2.5.2 · Source Section

    2.5.2 귀납적 추론과 ML 활용하기 — 불확실성 아래에서의 일반화

    귀납은 불완전한 데이터에서도 일반화한다.예측은 불확실성과 평가 조건을 함께 가져야 한다.

    ML은 비정형 텍스트를 구조화하거나 온톨지와 관계를 학습해 지식 베이스를 확장할 수 있습니다. 이어 관찰에서 패턴을 추상화해 모든 정보가 갖춰지지 않은 상황에서도 예측이나 제안을 만듭니다.

    이 능력은 처음 보는 사례를 다루게 하지만 오답 가능성을 없애지 않습니다. 훈련 데이터의 범위, 특징, 평가 집단과 불확실성을 함께 제시해야 예측을 논리적 사실로 오해하지 않습니다.

    §2.5.3 · Source Section

    2.5.3 추론 엔진에서 LLM의 역할 — 지식의 빈틈을 메우는 확률적 추론

    LLM은 모호한 입력과 지식의 빈틈에서 후보를 제안한다.확률적 제안은 검증과 우선순위 조정이 필요하다.

    환자 기록이 불완전하고 증상이 비특이적일 때 LLM은 의학 문헌에서 학습한 패턴을 이용해 여러 가능성을 동시에 검토하고 우선순위가 있는 진단 접근을 제안할 수 있습니다.

    KG 기반 추론과 결합하면 명시적 사실·관계와 맥락적 언어 해석을 함께 사용할 수 있습니다. 다만 LLM의 출력은 “빈틈을 메운 확정 사실”이 아니라 근거 확인을 기다리는 확률적 후보로 다뤄야 합니다.

    §2.6 · Source Section

    2.6 IAS에 대한 KG 접근법 — 상향식의 함정과 목적 주도 방식

    모든 데이터부터 모으는 상향식은 목표와 평가를 늦춘다.목적 주도 방식은 비즈니스 질문에서 필요한 데이터·KG·모델을 도출한다.

    저자들의 경험에 따르면, 사용 과제를 정하지 않고 여러 원천을 하나의 진실의 원천으로 통합하는 상향식 KG는 구조·식별자 정규화에 큰 비용을 쓰고도 관련 없는 데이터를 많이 남겨 실패하기 쉽습니다.

    목적 주도 방식은 비즈니스 이해에서 출발해 필요한 데이터 부분과 KG 구조를 정하고, 모델링·평가·배포를 반복합니다. LLM은 비정형 데이터의 개체·관계 추출과 질문 이해를 돕지만 프로젝트 목표를 대신하지 않습니다.

    그래프 데이터베이스의 스키마리스 유연성은 아무 규칙도 없다는 뜻이 아닙니다. 기존 기능을 해치지 않고 노드·관계를 확장할 수 있다는 뜻이며, 실제 과정에서는 반복 간 호환성을 위해 스키마와 검증 규칙을 사용합니다.

    핵심 용어와 출처

    지식 그래프(KG)
    개체와 의미 관계를 명시적으로 표현하고 조회·수정할 수 있는 지식 구조.
    대규모 언어 모델(LLM)
    대규모 텍스트의 통계 패턴을 매개변수에 학습해 자연어를 처리하는 모델.
    추론
    전제·규칙·관찰·패턴을 사용해 결론, 예측 또는 후보를 만드는 과정.
    provenance
    사실이나 관계가 어느 원천·과정·시점에서 왔는지 설명하는 계보 정보.
