SECTION 5.2

5.2 지식 추출의 핵심 개념 — 개체와 관계, 두 개의 기둥

점(개체)과 선(관계)이 그래프의 뼈대다

5.2
AIML QuantCORE CONCEPT

텍스트를 그래프로 바꾸는 일은 두 작업으로 압축된다

개체를 찾는 일과 개체를 잇는 관계를 뽑는 일. 서로 맞물린 이 둘이 어떤 지식 그래프든 그 뼈대를 이룬다.

ENTITY

개체 = 점

  • 사람·장소·조직·주제
  • 미리 정한 범주로 분류
  • 개체만 있으면 흩어진 점

RELATION

관계 = 선

  • 개체 쌍의 의미적 연결
  • 방향이 있어 순서가 중요
  • 선이 있어야 그래프가 됨

기억할 것 — NER은 점을 찾고, RE는 점을 잇는다.

일반 범주만으로는 부족하다

5.2.1

SECTION 5.2.2

5.2.2 관계 추출하기 — 개체들을 이어 주는 실

일관성이 그래프의 품질을 만든다

5.2.2
AIML QuantRELATION

같은 관계라도 문서마다 다르게 쓰면 그래프가 뒤죽박죽

“제인 오스틴은 구글에 고용되어 있다”에서 PERSON과 ORGANIZATION을 잇는 관계가 RE의 결과물이다.

SAME FACT

여러 표현

  • 제인 오스틴 -WORKS_FOR-> 구글
  • 구글 -EMPLOYS-> 제인 오스틴
  • 방향만 뒤집힌 같은 사실

RULE

일관성이 핵심

  • 문서 전반에 같은 이름·방향
  • 제각각이면 질의가 깨짐
  • 스키마를 미리 합의

기억할 것 — 개체(점)에 관계(선)를 더해야 비로소 진정한 지식 그래프다.

5.3 대규모 언어 모델로 지식 그래프 만들기 — 판을 바꾸는 도구

여러 전문 모델을 한 번의 통과로 대체한다

5.3
AIML QuantSOURCE VISUAL

LLM은 NER·상호참조·RE를 한 번에 처리한다

전통적 NLP는 여러 전문 모델을 잇지만, LLM은 한 번의 통과로 개체와 관계를 함께 뽑는다.

Chapter 5 · LLM 정신 모형 /
AIML QuantWHY / LIMIT

전이 학습이 강점을, 환각이 한계를 만든다

일반 과제에서 배운 패턴을 재사용해 라벨 데이터를 줄이고, 자연어 프롬프트만으로 과제를 수행한다.

STRENGTH

전이 학습 · 데이터 중심

  • 이미 배운 가중치를 재사용
  • 적은 라벨로 같은 정확도
  • 프롬프트 엔지니어링만으로

LIMIT

환각(hallucination)

  • 근거 없이 사실을 지어냄
  • 모를 때도 자신 있게 말함
  • 이 시점까지 미해결 문제

제안 — LLM에게 품질 높은 개체·관계·속성을 뽑게 해 더 깨끗한 그래프를 만든다.

SECTION 5.3.4

5.3.4 지식 그래프 구축: 전통적 NLP인가, LLM인가?

둘은 공존하거나 서로를 돕는다

5.3.4
AIML QuantDECISION

전통적 NLP는 여전히 설 자리가 있다

보안·대규모 비용·스트리밍 속도를 고려하면 NLP의 자리는 넓다. 둘은 서로의 학습 데이터를 만들 수도 있다.

전통적 NLP

속도 · 비용 · 보안

  • CPU로도 빠른 예측
  • 단순·저렴한 온프레미스
  • 단, 큰 초기 투자와 전문성

LLM

빠른 맞춤 · 올인원

  • 전이 학습·프롬프트로 빠르게
  • 한 번 통과, 깨끗한 출력
  • 단, GPU·대규모 비용·속도

결론 — “전통적 NLP가 설 자리가 있는가?” → “당연히 있다”.
