    0. 핵심 질문

    One SentenceKG의 검증 가능한 관계와 LLM의 자연어 능력은 어떻게 서로의 빈틈을 메우는가?

    지능형 시스템의 품질은 모델 하나의 유창함보다 어떤 지식을 기억하고, 어떤 방식으로 추론하며, 누가 결과를 검토하고 행동을 확정하는지에 달려 있습니다. 관계와 출처를 명시하는 KG와 언어 패턴을 다루는 LLM은 서로 다른 책임을 맡습니다.

    핵심은 기술을 많이 결합하는 것이 아니라 지식 표현, 언어 처리, 추론, 사람의 결정이 서로 다른 상태와 책임을 갖도록 만드는 데 있습니다. 결과가 사실인지 예측인지 권고인지 구분하고, 근거와 갱신 경로를 함께 남겨야 합니다.

    §1.1 · Source Section

    1.1 지식 그래프 — 기계에 사람의 지식을 심는 법

    KG는 개체·관계·속성으로 도메인 지식을 명시한다.구축·접근·결과 해석 비용이 확산을 막아 왔다.

    지식 그래프(KG)는 현실의 대상을 노드로, 의미 있는 연결을 관계로, 날짜·출처·설명 같은 맥락을 속성으로 표현합니다. 관계에 이름과 방향을 주기 때문에 단순한 연결망보다 “무엇이 무엇과 어떤 의미로 연결되는가”를 기계가 따라갈 수 있습니다.

    명시적 표현은 질병–증상–약물처럼 여러 단계를 건너는 질문과 설명 가능한 추론에 유리합니다. 그러나 비정형 텍스트에서는 언어·오타·대명사·문체·전문 용어를 해석해야 하고, 서로 다른 원천을 공통 스키마에 맞추는 비용도 큽니다.

    세 가지 병목

    만드는 비용, 여러 홉을 질의하는 접근 비용, 흩어진 결과를 비전문가가 이해할 설명으로 바꾸는 전달 비용을 따로 봐야 합니다.

    §1.2 · Source Section

    1.2 대규모 언어 모델 — 자연어라는 장벽을 허무는 열쇠

    전이 학습은 일반 언어 패턴을 여러 과제에 재사용한다.유창함은 최신 사실과 근거를 보장하지 않는다.

    전이 학습은 일반 과제에서 배운 패턴을 관계 추출 같은 새로운 과제에 다시 쓰는 방식입니다. 과제마다 대규모 라벨 데이터와 전용 모델을 처음부터 만드는 대신, 사전학습 모델에 지시와 소량의 조정을 더해 재사용할 수 있습니다.

    트랜스포머 기반 LLM의 성능은 모델 복잡도, 학습 말뭉치의 양·품질, 다양한 과제를 다음 토큰 예측으로 다루는 능력이 함께 만든 결과입니다. 토큰화는 텍스트를 계산 가능한 단위로 바꾸지만, 모델 내부의 지식은 여전히 통계 패턴이라 특정 사실의 출처를 바로 가리키거나 부분 수정하기 어렵습니다.

    구분할 것

    자연어를 잘 읽고 쓰는 능력과 도메인 사실을 최신·정확·추적 가능하게 보증하는 능력은 같은 것이 아닙니다.

    §1.3 · Source Section

    1.3 KGs와 LLM은 함께일 때 더 강하다 — 서로를 떠받치는 관계

    LLM은 KG 구축·질의·요약을 돕는다.KG는 LLM 답변에 도메인 사실·최신성·경로 근거를 공급한다.

    LLM은 비정형 텍스트에서 개체와 관계 후보를 뽑고, 자연어 질문을 그래프 질의로 바꾸며, 여러 노드와 관계에 흩어진 결과를 문장으로 설명할 수 있습니다. 후보 추출과 질의 생성은 편의 기능이지 곧바로 검증된 사실이나 안전한 실행이 아닙니다.

    반대로 KG는 검증·갱신 가능한 사실과 관계 경로를 제공해 답변을 특정 도메인에 붙들어 맬 수 있습니다. 이 결합은 환각을 줄일 수 있지만, 그래프 자체가 틀렸거나 오래됐고 검색 경로가 잘못되면 정확성을 보장하지 못합니다.

    역할 계약

    LLM은 언어 계층, KG는 지식 계층, 검증과 권한은 운영 계층이 맡을 때 서로의 강점이 실제 시스템 품질로 이어집니다.

    §1.4 · Source Section

    1.4 데이터 기반 애플리케이션의 패러다임 전환 — 왜 판이 바뀌는가

    지식을 애플리케이션마다 복제하지 않고 공유 계층으로 둔다.단일 원천은 소유권·갱신·충돌 규칙까지 포함해야 한다.

    데이터 사일로마다 지식과 규칙을 다시 구현하면 비용과 불일치가 늘어납니다. 공유 KG는 여러 애플리케이션이 같은 개체·관계·출처를 활용하도록 해 지능적 행동의 공통 기반을 제공합니다.

    책은 McKinsey & Company의 추산을 인용해 데이터 파편화 해소가 단기적으로 연간 데이터 지출을 5–15% 줄일 수 있다고 소개합니다. 이 수치는 인용된 맥락의 추산이며 모든 조직에 자동 적용되는 보장은 아닙니다.

    §1.4.1 · Source Section

    1.4.1 지식 그래프의 네 기둥 — KG를 KG답게 만드는 것

    진화·의미·통합·학습이 KG의 네 기둥이다.네 요소는 저장 형식이 아니라 운영되는 지식 계층의 성질을 설명한다.

    진화는 새 사실과 구조를 받아들이는 능력, 의미는 유형과 관계 규칙을 명시하는 능력, 통합은 서로 다른 원천을 공통 개체와 문맥으로 연결하는 능력, 학습은 질의·분석·추론으로 명시되지 않은 통찰을 얻는 능력입니다.

    네 기둥 중 하나만 강해서는 충분하지 않습니다. 새 데이터를 넣기 쉬워도 의미와 출처가 없으면 설명하기 어렵고, 온톨로지가 정교해도 갱신 책임이 없으면 곧 낡습니다.

    §1.5 · Source Section

    1.5 KGs와 LLM으로 데이터 기반 애플리케이션 만들기

    결합 가치는 관계 지식과 자연어 처리가 함께 필요한 문제에서 커진다.사례별 실패 비용과 검증 수준은 다르다.

    의료와 고객 지원은 도메인이 다르지만 여러 원천의 관계 지식, 비정형 문서, 자연어 질문, 근거 있는 다음 행동이 동시에 필요하다는 공통점이 있습니다. 결합 여부는 유행이 아니라 문제의 모양으로 판단해야 합니다.

    이 절의 사례는 KG와 LLM이 모든 문제를 자동 해결한다는 뜻이 아닙니다. 어떤 정보를 사실로 승격할지, 누가 승인할지, 잘못된 연결과 응답을 어떻게 되돌릴지가 함께 설계되어야 합니다.

    §1.5.1 · Source Section

    1.5.1 예시 사례: 신약 발견과 개발

    신약 개발은 생물학·화학·문헌 지식을 통합해야 한다.가설과 검증된 사실을 분리해야 한다.

    KG는 유전자·단백질·질병·약물과 그 관계 유형을 연결해 여러 규모의 생물학적 상호작용을 탐색하게 합니다. LLM은 논문·임상 보고서 같은 비정형 문서에서 개체와 관계 후보를 찾고 연구 질문을 언어로 다룰 수 있습니다.

    문헌에서 추출한 관계나 모델이 제안한 가설은 곧바로 확정 사실이 아닙니다. 출처, 실험 상태, 검증 수준을 관계와 함께 보존해야 가설 생성 속도가 신뢰성 손실로 바뀌지 않습니다.

    §1.5.2 · Source Section

    1.5.2 예시 사례: 고객 지원을 위한 대화형 AI

    대화는 개념과 관계를 중심으로 이어진다.개인화에는 권한·최신 정책·출처 통제가 필요하다.

    KG는 고객·제품·계약·정책처럼 대화에 필요한 개념과 관계를 구조화하고, LLM은 사용자의 의도를 해석하고 되묻고 설명합니다. 구조화된 지식이 없으면 답변은 유창해도 일반적이거나 낡은 정보에 머물 수 있습니다.

    고객 지원에서는 타 고객 정보 노출, 만료된 정책 적용, 승인되지 않은 실행이 특히 위험합니다. 자연스러운 문장보다 먼저 조회 권한과 적용 시점, 답변에 사용한 근거를 통제해야 합니다.

    §1.5.3 · Source Section

    1.5.3 KG를 쓸지 말지 판단하기

    KG는 관계·통합·출처·진화가 병목일 때 고려한다.LLM은 비정형 추출·질문 해석·대화·요약이 병목일 때 고려한다.

    데이터 사일로를 조화시키고, 정형·비정형 원천을 의미 있게 연결하고, 변화하는 구조와 provenance를 추적해야 한다면 KG가 유력합니다. 고급 검색·추천·네트워크 분석처럼 관계 구조 자체가 가치의 원천인 경우도 마찬가지입니다.

    비정형 문서에서 개체·관계를 찾고, 복잡한 질문을 해석하고, 대화형 인터페이스와 글 요약을 제공해야 한다면 LLM이 유용합니다. 어느 하나라도 필요하다고 해서 두 기술을 최대 규모로 도입할 필요는 없으며, 대표 질문과 작은 스키마로 가치를 확인하는 편이 안전합니다.

    §1.6 · Source Section

    1.6 지식 그래프 기술 — RDF와 LPG, 두 갈래 길

    RDF는 표준 진술·상호운용성·의미 추론에 강하다.LPG는 관계 속성과 경로 탐색을 직접 다루기 쉽다.

    RDF는 주어–술어–목적어 트리플로 지식을 표현하고 SPARQL로 질의합니다. 전역 술어와 웹 표준을 사용해 서로 다른 그래프를 연결하고 온톨로지 기반 의미 추론을 하는 데 적합합니다.

    LPG는 노드와 관계가 각각 속성을 가지며 openCypher나 Gremlin으로 경로를 탐색합니다. 개별 관계에 출처·신뢰도 같은 정보를 직접 달고 순회하는 응용에 편리합니다. 두 방식은 경쟁 제품이라기보다 서로 다른 최적화 방향이며 혼합될 수도 있습니다.

    §1.6.1 · Source Section

    1.6.1 분류체계와 온톨로지 — 그래프에 '의미'를 불어넣기

    분류체계는 넓음–좁음 계층을 조직한다.온톨로지는 동일성·서로소·제약까지 표현한다.

    분류체계는 탈것 ⊃ 자동차 ⊃ 세단처럼 범주의 세로 질서를 만듭니다. 온톨로지는 여기에 “자동차와 오토모빌은 같다”, “자동차와 자전거는 서로소다” 같은 가로 규칙과 개수 제약을 더해 기계 추론의 근거를 제공합니다.

    완전하고 경직된 온톨로지를 먼저 만드는 대신, 현재 질문과 오류를 해결하는 딱 필요한 만큼의 의미를 채택할 수 있습니다. 부분 온톨로지는 확장성을 주지만, 어떤 규칙을 생략했는지 명시해야 과도한 추론을 막을 수 있습니다.

    §1.7 · Source Section

    1.7 이 책은 KGs와 LLM을 어떻게 가르치는가

    비즈니스 목표에서 데이터와 알고리즘으로 내려간다.모델링·수집·검증·분석·자연어 질의를 한 생애주기로 배운다.

    이 책은 목표를 먼저 정하고 필요한 데이터와 스키마를 모델링한 뒤, 정형 원천을 매핑하고 LLM으로 비정형 텍스트의 개체·관계 후보를 추출하는 흐름을 따릅니다. 수집한 정보는 무결성과 정확성을 검증한 뒤 그래프에 통합합니다.

    후반부에서는 그래프 신경망 같은 ML 분석, 그래프 질의와 시각화, 자연어 질문을 위한 LLM 활용으로 확장합니다. 도구 목록보다 중요한 것은 각 단계의 입력·산출물·검증 책임이 연결된다는 점입니다.

    핵심 용어와 출처

    지식 그래프(KG)
    개체와 의미 관계를 명시적으로 표현하고 조회·수정할 수 있는 지식 구조.
    대규모 언어 모델(LLM)
    대규모 텍스트의 통계 패턴을 매개변수에 학습해 자연어를 처리하는 모델.
    추론
    전제·규칙·관찰·패턴을 사용해 결론, 예측 또는 후보를 만드는 과정.
    provenance
    사실이나 관계가 어느 원천·과정·시점에서 왔는지 설명하는 계보 정보.
