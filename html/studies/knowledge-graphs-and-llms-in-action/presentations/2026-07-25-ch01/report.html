    0. 왜 KG와 LLM을 함께 보는가

    한 문장으로LLM은 KG를 만들고 묻고 설명하는 언어 장벽을 낮추고, KG는 LLM에 최신 도메인 지식과 추적 가능한 관계를 공급해 서로의 약점을 보완합니다.

    생성형 AI는 자연어를 유창하게 다루지만, 전문 지식·높은 정확성·설명 가능성이 필수인 영역에서는 환각과 오래된 정보, 맥락 관계의 부재가 문제가 됩니다. KG는 개체·관계·속성으로 지식을 명시해 이 빈틈을 메울 수 있지만, 비정형 텍스트에서 지식을 뽑고 복잡한 그래프를 질의하고 결과를 설명하는 비용이 큽니다. 저자는 이처럼 맥락과 설명 가능성을 결합하는 방향을 “AI의 제3의 물결”이라는 관점 [1]과 연결합니다.

    이 장은 먼저 KG와 LLM의 작동 방식과 한계를 각각 세운 뒤, 양방향 보완 관계를 설명합니다. 이어 공유 지식 계층이 만드는 패러다임 전환, 신약 개발·고객 지원 사례, 도입 판단 질문, RDF·LPG와 온톨로지 선택으로 내려갑니다.

    교재 §1.1 · 핵심 개념

    1.1 지식 그래프 — 기계에 사람의 지식을 심는 법

    KG는 개체·관계·속성으로 도메인 지식을 명시한다.구축·접근·결과 해석 비용이 확산을 막아 왔다.

    지식 그래프(KG)는 현실의 대상을 노드로, 의미 있는 연결을 관계로, 날짜·출처·설명 같은 맥락을 속성으로 표현합니다. 관계에 이름과 방향을 주기 때문에 단순한 연결망보다 “무엇이 무엇과 어떤 의미로 연결되는가”를 기계가 따라갈 수 있습니다.

    의료 그래프라면 질병·약물·화합물·해부학적 구조를 연결해 여러 홉에 걸친 질문과 설명 가능한 추론을 지원합니다. 정형·반정형 데이터는 항목과 유형이 어느 정도 분리돼 있어 공통 그래프 스키마로 매핑할 수 있지만, 비정형 텍스트는 여러 언어·오타·대명사·문체·전문 용어까지 해석해야 합니다.

    구축 뒤에도 장벽이 남습니다. 사용자는 스키마와 질의 언어를 알아야 여러 홉을 탐색할 수 있고, 여러 노드에 흩어진 결과를 비전문가가 이해할 설명으로 다시 조립해야 합니다. Google 검색의 “문자열이 아닌 사물” 접근과 분석가의 조사 질의는 KG의 가치를 보여 주지만, 전자는 검색에 국한되고 후자는 전용 인터페이스와 전문성이 필요하다는 사례입니다.

    세 가지 병목

    만드는 비용, 여러 홉을 질의하는 접근 비용, 흩어진 결과를 비전문가가 이해할 설명으로 바꾸는 전달 비용을 따로 봐야 합니다.

    교재 §1.2 · 핵심 개념

    1.2 대규모 언어 모델 — 자연어라는 장벽을 허무는 열쇠

    전이 학습은 일반 언어 패턴을 여러 과제에 재사용한다.규모·데이터·다음 토큰 예측이 LLM의 범용성을 만든다.

    전이 학습은 일반 과제에서 배운 패턴을 관계 추출 같은 새로운 과제에 다시 쓰는 방식입니다. 과제마다 대규모 라벨 데이터와 전용 모델을 처음부터 만드는 대신, 사전학습 모델에 지시와 소량의 조정을 더해 재사용합니다. 이 전환 덕분에 도메인마다 별도 NLP 모델을 만들지 않고도 프롬프트를 바꿔 개체·관계 추출을 시도할 수 있게 됐습니다.

    책은 GPT-2 [5], GPT-4 [5], Gopher [6], PaLM [7]을 규모 확장의 대표 사례로 들고 이를 “데이터의 불합리한 효과성” [8]과 연결합니다. 트랜스포머 기반 LLM의 성능은 서로 맞물린 세 요소에서 나옵니다. 첫째는 모델 복잡도, 둘째는 학습 말뭉치의 양과 품질, 셋째는 다양한 언어 과제를 다음 토큰 예측이라는 하나의 문제로 환원하는 능력입니다. 스케일링 법칙은 큰 모델이 같은 손실 수준에 더 적은 샘플로 도달할 수 있음을 보였지만, 나쁜 데이터가 나쁜 예측을 만든다는 사실은 바뀌지 않아 데이터 중심 접근이 중요합니다.

    토큰화는 텍스트를 모델이 계산할 단위로 나눕니다. 모델은 이 토큰들의 통계 패턴을 매개변수에 암묵적으로 저장하므로, 자연어를 유연하게 다루는 능력과 특정 사실의 출처를 가리키거나 최신 상태로 부분 수정하는 능력은 구분해야 합니다.

    AIML Quant 보충 · 읽기 경계

    유창함을 최신 사실성과 동일시하지 말고, 도메인 지식의 출처·갱신 시점·검증 경로는 별도 계층에서 확인합니다.

    교재 §1.3 · 결합 원리

    1.3 KGs와 LLM은 함께일 때 더 강하다 — 서로를 떠받치는 관계

    LLM은 KG 구축·질의·요약을 돕는다.KG는 LLM 답변에 정확성·최신성·설명 가능성을 보탠다.

    LLM은 비정형 텍스트에서 개체와 관계를 뽑아 KG 구축을 단순화하고, 자연어 질문을 그래프 질의로 바꾸며, 여러 노드와 관계에 흩어진 결과를 글로 요약합니다. 이 세 역할은 기존에 도메인별 NLP 모델, 스키마·질의 언어 전문성, 결과 해석 인터페이스가 요구하던 장벽을 낮춥니다.

    반대로 KG는 구조화되고 검증된 지식으로 환각을 줄일 사실의 토대를 제공하고, 계속 갱신되는 외부 상태를 KG 기반 프롬프팅이나 GraphRAG로 공급하며, 사용자가 따라가 검증할 관계 경로로 설명 가능성을 높입니다. 그림 1.5는 LLM의 암묵 지식·언어 처리·일반화와 KG의 정확성·해석 가능성·도메인·진화 지식을 각각의 약점과 맞대어 보여 줍니다.

    AIML Quant 보충 · 운영 경계

    LLM 추출물은 후보이고 KG도 자동으로 참이 아닙니다. 스키마·출처·갱신 상태를 검증하고, 잘못된 검색 경로까지 점검해야 보완 관계가 실제 품질로 이어집니다.

    교재 §1.4 · 패러다임 전환

    1.4 데이터 기반 애플리케이션의 패러다임 전환 — 왜 판이 바뀌는가

    동질적 데이터베이스의 목적별 앱에서 연결 중심의 공유 지식 계층으로 이동한다.RDF와 LPG는 사람과 기계가 함께 읽는 관계 표현을 제공한다.

    전통적 방식은 구조화되고 동질적인 데이터베이스 위에 특정 목적의 시스템을 만듭니다. 정해진 요구에는 잘 맞지만, 사용자에 적응하고 이질적 데이터를 통합해야 하는 복잡한 도메인에서는 같은 지식과 규칙이 사일로마다 갈라집니다. KG는 그래프 패턴 매칭과 순회로 관계를 발견하고, RDF와 LPG로 사람이 해석하면서 기계도 처리할 수 있는 공유 지식 표현을 만듭니다.

    책은 McKinsey & Company의 추산을 인용해 데이터 파편화 해소가 단기적으로 연간 데이터 지출을 5–15% 줄일 수 있다고 소개합니다. 이 수치는 인용된 맥락의 추산이지 모든 조직의 보장값은 아닙니다. 핵심 주장은 사일로를 연결하면 데이터 접근 장벽을 낮추고 거버넌스를 강화하는 공통 지식 원천을 만들 수 있다는 것입니다.

    교재 §1.4.1 · KG의 정의

    1.4.1 지식 그래프의 네 기둥 — KG를 KG답게 만드는 것

    진화·의미·통합·학습이 KG의 네 기둥이다.네 요소는 저장 형식이 아니라 운영되는 지식 계층의 성질을 설명한다.

    저자들은 KG를 “유형이 지정된 개체와 속성, 의미 있는 이름의 관계로 구성되고, 특정 도메인의 정형·비정형 데이터를 통합해 사람과 기계를 위한 지식을 만드는 끊임없이 진화하는 그래프 구조”로 정의합니다.

    진화는 새 사실과 구조를 받아들이는 능력, 의미는 유형·동일성·이행·역관계 같은 규칙을 명시해 설명과 추론을 가능하게 하는 능력입니다. 통합은 형식과 출처가 다른 원천을 공통 개체와 문맥으로 연결하고, 학습은 질의·시각화·중심성·최단 경로·커뮤니티 분석과 규칙·ML을 통해 명시되지 않은 통찰을 얻습니다.

    AIML Quant 보충 · 운영 점검

    새 데이터를 넣기 쉬워도 의미와 출처가 없으면 설명하기 어렵고, 온톨로지가 정교해도 갱신 책임이 없으면 곧 낡습니다. 네 기둥을 독립 체크리스트로 보지 말고 함께 점검합니다.

    교재 §1.5 · 적용 사례

    1.5 KGs와 LLM으로 데이터 기반 애플리케이션 만들기

    결합 가치는 관계 지식과 자연어 처리가 함께 필요한 문제에서 커진다.의료 사례는 공개 데이터가 풍부하고 다른 복잡한 도메인으로 일반화하기 좋다.

    책은 의료를 반복 사례로 사용합니다. 공개 데이터가 풍부해 현실적인 예를 만들 수 있고, 여러 전문 분야와 원천을 통합하며 높은 정확성이 필요한 문제 구조가 다른 도메인에도 옮겨가기 쉽기 때문입니다. 신약 개발과 고객 지원은 서로 다르지만 관계 지식, 비정형 문서, 자연어 질문을 함께 다룬다는 공통점이 있습니다.

    AIML Quant 보충 · 적용 경계

    결합 여부는 유행이 아니라 문제의 모양으로 판단합니다. 어떤 추출물을 사실로 승격할지, 누가 승인할지, 잘못된 연결과 응답을 어떻게 되돌릴지도 함께 설계해야 합니다.

    교재 §1.5.1 · 신약 개발

    1.5.1 예시 사례: 신약 발견과 개발

    신약 개발은 생물학·화학·문헌 지식을 통합해야 한다.KG는 관계의 맥락을, LLM은 비정형 문헌 처리를 맡는다.

    신약 개발은 비용과 실패 확률이 높고 생물학부터 화학까지 여러 규모의 지식을 통합해야 합니다. KG는 유전자·단백질·질병·약물을 유형화된 관계로 연결해 이행적 연결과 추론을 가능하게 하고, 여러 데이터 지점을 올바른 맥락에 놓으면서 무결성·정확성·일관성을 관리합니다.

    LLM은 과학 논문·임상 보고서·데이터베이스의 비정형 텍스트를 분석해 개체와 잠재 관계를 추출하고, 화학 구조와 실험 결과에 관한 텍스트 마이닝으로 KG 확장과 가설 생성을 돕습니다.

    AIML Quant 보충 · 증거 상태

    문헌에서 추출한 관계와 모델이 제안한 가설은 확정 사실이 아닙니다. 출처·실험 상태·검증 수준을 함께 보존해야 속도 향상이 신뢰성 손실로 바뀌지 않습니다.

    교재 §1.5.2 · 대화형 AI

    1.5.2 예시 사례: 고객 지원을 위한 대화형 AI

    대화는 개념과 관계를 중심으로 이어진다.KG의 사실 배경과 LLM의 언어 능력이 함께 필요하다.

    개인화된 어시스턴트는 질문에 답할 뿐 아니라 필요할 때 되물으며, 일반 전문성과 사용자별 요청을 결합해야 합니다. Zhang 등 [14]이 지적하듯 언어 모델의 답은 반복적이고 알맹이가 없을 수 있으며, 추가 맥락이 없으면 폭넓은 언어 능력만으로 이를 해결하기 어렵습니다.

    Zhang 등 [14]의 표현처럼 대화는 흔히 지식을 중심으로 전개됩니다. KG는 고객·제품·계약·정책 같은 개념과 관계를 연결해 대화를 사실에 붙들고, LLM은 의도를 해석하고 복잡한 질의를 탐색하며 구조적 결과를 자연스러운 문장으로 바꿉니다. 이렇게 외부·내부의 구조화된 지식이 대화의 배경 맥락이 됩니다.

    AIML Quant 보충 · 서비스 안전

    고객 지원에서는 조회 권한, 정책 적용 시점, 답변 근거를 통제해 타 고객 정보 노출·만료 정책 적용·승인되지 않은 실행을 막아야 합니다.

    교재 §1.5.3 · 도입 판단

    1.5.3 KG를 쓸지 말지 판단하기

    KG는 관계·통합·출처·진화가 병목일 때 고려한다.LLM은 비정형 추출·질문 해석·대화·요약이 병목일 때 고려한다.

    데이터 사일로를 일관된 개관으로 조화시키고, 정형·비정형 원천을 의미 있게 연결하며, 변화하는 구조와 provenance를 추적해야 한다면 KG를 고려합니다. 고급 검색·추천, 커뮤니티와 상호의존성의 시각화, 관계 구조를 이용하는 ML처럼 연결 자체가 가치의 원천인 경우도 해당합니다.

    비정형 문서에서 개체·관계를 찾고, 정확한 답을 위해 복잡한 질문을 해석하며, 대화형 인터페이스와 종합 결과의 글 요약이 필요하면 LLM을 고려합니다. 책의 판단은 이런 요구가 하나라도 있다면 KG 기반 해법을 LLM이 강화할 수 있다는 것입니다.

    AIML Quant 보충 · 최소 실험

    대표 사용자 질문과 작은 스키마로 실제 가치와 오류 비용을 먼저 확인하면 두 기술을 필요 이상으로 크게 도입하는 일을 피할 수 있습니다.

    교재 §1.6 · 기술 선택

    1.6 지식 그래프 기술 — RDF와 LPG, 두 갈래 길

    RDF는 표준 진술·상호운용성·의미 추론에 강하다.LPG는 관계 속성과 경로 탐색을 직접 다루기 쉽다.

    RDF는 주어–술어–목적어 트리플로 지식을 표현하고 SPARQL로 질의합니다. 전역 술어와 웹 표준을 사용해 서로 다른 그래프를 연결하고 온톨로지 기반 의미 추론을 하는 데 적합합니다.

    LPG는 노드와 관계가 각각 속성을 가지며 openCypher나 Gremlin으로 경로를 탐색합니다. 개별 관계에 출처·신뢰도 같은 정보를 직접 달고 순회하는 응용에 편리합니다. 두 방식은 경쟁 제품이라기보다 서로 다른 최적화 방향이며 혼합될 수도 있습니다.

    교재 §1.6.1 · 의미 체계

    1.6.1 분류체계와 온톨로지 — 그래프에 '의미'를 불어넣기

    분류체계는 넓음–좁음 계층을 조직한다.온톨로지는 동일성·서로소·제약까지 표현한다.

    분류체계는 탈것 ⊃ 자동차 ⊃ 세단처럼 범주의 세로 질서를 만듭니다. 온톨로지는 여기에 “자동차와 오토모빌은 같다”, “자동차와 자전거는 서로소다” 같은 가로 규칙과 개수 제약을 더해 기계 추론의 근거를 제공합니다.

    완전하고 경직된 온톨로지를 먼저 만드는 대신, 현재 질문과 오류를 해결하는 딱 필요한 만큼의 의미를 채택할 수 있습니다. 부분 온톨로지는 확장성을 주지만, 어떤 규칙을 생략했는지 명시해야 과도한 추론을 막을 수 있습니다.

    교재 §1.7 · 학습 여정

    1.7 이 책은 KGs와 LLM을 어떻게 가르치는가

    비즈니스 목표에서 데이터와 알고리즘으로 내려간다.모델링·수집·검증·분석·자연어 질의를 한 생애주기로 배운다.

    이 책은 목표를 먼저 정하고 필요한 데이터와 스키마를 모델링한 뒤, 정형 원천을 매핑하고 LLM으로 비정형 텍스트의 개체·관계 후보를 추출하는 흐름을 따릅니다. 수집한 정보는 무결성과 정확성을 검증한 뒤 그래프에 통합합니다.

    후반부에서는 그래프 신경망 같은 ML 분석, 그래프 질의와 시각화, 자연어 질문을 위한 LLM 활용으로 확장합니다. 도구 목록보다 중요한 것은 각 단계의 입력·산출물·검증 책임이 연결된다는 점입니다.

    핵심 용어와 출처

    지식 그래프(KG)
    개체와 의미 관계를 명시적으로 표현하고 조회·수정할 수 있는 지식 구조.
    대규모 언어 모델(LLM)
    대규모 텍스트의 통계 패턴을 매개변수에 학습해 자연어를 처리하는 모델.
    추론
    전제·규칙·관찰·패턴을 사용해 결론, 예측 또는 후보를 만드는 과정.
    provenance
    사실이나 관계가 어느 원천·과정·시점에서 왔는지 설명하는 계보 정보.
